**候補 C — native mode で動画リンクを表示** ([PR #64](https://github.com/yyamazaki-lym/raid-repository/pull/64)): [src/app/(portal)/page.tsx](src/app/(portal)/page.tsx) の native 分岐で `sessionVideoLinks={}` 固定だったのを `buildSessionVideoLinkMap(nativeSessions)` 呼出しに変更 (2 行追加)。既存 [src/lib/categories/session-video-link.ts](src/lib/categories/session-video-link.ts) の `buildSessionVideoLinkMap()` は `ScheduleSession[]` 汎用入力 → native session そのまま流用可、マッチ key (`rawDate` + `date`) は両 mode で互換性確認済 ([src/lib/schedule/native-fetch.ts](src/lib/schedule/native-fetch.ts) の `parsed_date` → `new Date()` 変換が sync mode の Date オブジェクトと等価)。schema 変更なし、新規 server action なし。FFLogs 部分は別 TODO 起票で対応。

**候補 B — 通知時刻 HH 設定 + 毎時 cron への pivot** ([PR #66](https://github.com/yyamazaki-lym/raid-repository/pull/66)): 当初設計の「24h 前 / 開始時固定リマインダー追加」ではなく、ユーザー判断「自動通知は 12 時以外の可能性を考えると手動で時間設定出来た方がよさそう」を反映し **「既存 12:00 JST 固定を任意 HH (0-23) に変更可能にする」** に pivot。実装コスト軽減 + UX 価値の確実な向上を両立。
  - **schema** ([supabase/schema.sql](supabase/schema.sql)): app_settings seed に `native_schedule_discord_notify_hour='12'` を 1 key 追加 (HH 文字列, JST 時刻, default '12' で既存 12:00 運用を後方互換維持)
  - **cron schedule** ([vercel.json](vercel.json)): `notify-native-schedule` の `0 3 * * *` (12:00 JST 固定) → `0 * * * *` (毎時 0 分発火) に変更。これで JST 0:00〜23:00 の任意時刻 cron 発火に対応
  - **時刻判定 skip** ([src/app/api/cron/notify-native-schedule/route.ts](src/app/api/cron/notify-native-schedule/route.ts)): `dispatchNoonNotifyForToday()` の enabled skip 直後に挿入。target hour と現在 JST hour が一致するときのみ実通知、不一致なら `{ ok: true, posted: 0, skipped: 0 }` で早期 return
  - **server action** ([src/lib/server/native-schedule-actions.ts](src/lib/server/native-schedule-actions.ts)): `setNativeScheduleDiscordNotifyHourAction(hour)` を admin gate + 0-23 validate + `upsert` with `onConflict: 'key'` + 空文字列 DELETE → default '12' 復帰、で実装
  - **settings UI** ([src/components/portal/settings/native-discord-notify-section.tsx](src/components/portal/settings/native-discord-notify-section.tsx)): 「通知時刻 (JST)」select (00:00〜23:00) を即時保存パターン (`useTransition` + parent-sync `useEffect` + toast + `onChanged` + `router.refresh()`) で追加
  - **adminAux 拡張** ([src/lib/schedule/native-admin-client.ts](src/lib/schedule/native-admin-client.ts)): `fetchNativeScheduleAdminAux()` の Promise.all に hour 取得追加、`NativeAdminAux` 型に `discordNotifyHour: string` (default '12') を追加
  - **dedup**: 既存 `last_notified_at IS NULL` 1 行は不変、「同日 1 セッション 1 通」運用は維持
  - **制約**: Vercel cron 1 時間粒度のため HH 単位のみサポート (9:30 等は不能、9:00 になる)。設定値が無効 (例 "abc") の場合は default '12' を使用

**FFLogs 部分は TODO #73 に分離**: [src/lib/server/fflogs.ts](src/lib/server/fflogs.ts) の `linkReportsToSessions()` は現状 `schedule_past_sessions` 直読みなので native mode の sessions では FFLogs auto-link が動かない。native sessions 対応への拡張 + `schedule_past_session_logs` の sync/native 統合 vs 別テーブル新設の設計議論 + `schedule_past_sessions` 直読みからの脱却、を新規 TODO #73 として未完了 TODO 一覧に分離。詳細は `.claude/plans/todo-2-claude-handoff-md-spicy-seahorse.md` の「FFLogs 部分の扱い (本 TODO から除外)」節。
