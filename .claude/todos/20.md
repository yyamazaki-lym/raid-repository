# TODO #20 — Vercel ドメイン変更

## 目的

Vercel プロジェクトのデフォルト `*.vercel.app` サブドメインを「raid 固定の固定名らしい英数字プリフィックス」付きに変更する。例: `raid-repository.vercel.app` → `yurutto-raid-repository.vercel.app`。

固有名詞を URL に含めることで、複数固定で同コードベースを fork して使う場合に固定ごとの識別性を上げる狙い。

## コード側結論

**コード変更は不要**。

- すべての OAuth callback / redirect は `window.location.origin` または `req.url` の origin から動的取得しており、ドメイン非依存。
- 設定値はすべて環境変数または外部サービス側 URL (= portal ドメインに依存しない)。
- 唯一のドキュメント更新: `.env.local.example` の OAuth setup コメントに新ドメイン例 + FFLogs OAuth エントリを追記済 (この TODO で実施)。

## 外部 Dashboard 作業手順

### 全体方針

Vercel の `*.vercel.app` サブドメインは「プロジェクト名 = サブドメイン名」で自動付与される。任意の `<prefix>-raid-repository.vercel.app` を取るには **プロジェクト名をリネーム** する。

### Step 1 — Vercel プロジェクトリネーム

1. https://vercel.com/yyamazaki-lyms-projects/raid-repository を開く
2. **Settings → General → Project Name** を新名 (例: `yurutto-raid-repository`) に変更
3. Save → 新ドメイン `<新名>.vercel.app` が自動付与
4. **Settings → Domains** で新ドメインが Production バッジ付きで表示されていることを確認
5. 旧 `raid-repository.vercel.app` は Vercel の grace period 中は redirect として残る (動作確認完了後に手動削除可)

> ⚠️ リネーム直後 1〜2 分は新ドメインで 502 が出ることあり。HTTP 200 を確認してから次へ。

### Step 2 — Supabase Auth 設定更新

1. https://supabase.com/dashboard → 該当プロジェクトを開く
2. **Authentication → URL Configuration**
3. **Site URL** を新ドメインに更新: `https://<新名>.vercel.app`
4. **Redirect URLs** に新ドメインのエントリを **追加** (旧は当面残す):
   ```
   https://<新名>.vercel.app/auth/callback
   https://<新名>.vercel.app/**
   http://localhost:3000/auth/callback        ← 既存維持
   https://raid-repository.vercel.app/auth/callback  ← 移行期間中は維持
   ```
5. Save
6. 動作確認後、旧ドメインのエントリを削除

> 💡 Discord Developer Portal の OAuth Redirects は `https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback` を指している (= portal ドメイン非依存) ため Discord 側変更は **不要**。

### Step 3 — FFLogs OAuth Application 設定更新

1. https://www.fflogs.com/api/clients/ にログイン
2. portal クライアントの **Edit**
3. **Redirect URLs** を更新 (FFLogs は exact match):
   - 旧: `https://raid-repository.vercel.app/api/auth/fflogs/callback`
   - 新: `https://<新名>.vercel.app/api/auth/fflogs/callback`
   - 移行期間中は両方記載 (FFLogs は複数 URI 許可)
4. Save
5. 動作確認後、旧 URL 削除

> ⚠️ 移行期間中に旧ドメインで FFLogs OAuth セッション再取得を試みると `redirect_uri_mismatch` エラー。設定 → FFLogs セッション cookie の再投入は必ず新ドメイン側で実施。

### Step 4 — 動作確認チェックリスト

新ドメインで以下を順に確認:

- [ ] `https://<新名>.vercel.app/` → ログイン画面表示
- [ ] Login → Discord OAuth フロー完走 → portal TOP 着地 (= Supabase 設定反映済)
- [ ] 設定ダイアログ → FFLogs セッション cookie 再投入 → admin で取得成功 (= FFLogs Redirect URI 反映済)
- [ ] Discord 取込 / カテゴリ編集 / 動画追加 etc が admin として実行可能
- [ ] スケジュール TOP / カテゴリ詳細ページが Edge / Node runtime ともに 200 で配信
- [ ] 旧 `https://raid-repository.vercel.app/` → 308 redirect で新ドメインへ

### Step 5 — 後片付け (動作確認完了後) ✅ 2026-05-01 完了

- [x] **Vercel Domains 旧 alias** — Remove ではなく **308 Permanent Redirect → 新ドメイン** に切替。`Settings → Domains → raid-repository.vercel.app` を編集し `Connect to an environment` から `Redirect to Another Domain (308)` へ変更、転送先に `yurutto-raid-repository.vercel.app` を指定。curl 検証済 (`/` `/category` ともに `308 + Location: https://yurutto-raid-repository.vercel.app/<path>`)。Remove せず redirect 維持を選んだ理由: 旧ドメインのブックマーク勢を新ドメインに自動誘導するため (404 を避ける、SEO 的にも 308 = permanent が筋)。
- [x] **Supabase Auth Redirect URLs** から旧エントリ 3 件削除 (`https://raid-repository.vercel.app/auth/callback`, `https://raid-repository.vercel.app/**`, および過去 preview deploy 用 `https://raid-repository-git-claude-wizar-...vercel.app/auth/callback`)。残存は `http://localhost:3000/auth/callback`, `http://localhost:3000/**`, `https://yurutto-raid-repository.vercel.app/auth/callback`, `https://yurutto-raid-repository.vercel.app/**` の 4 件 (Total 4)。Site URL も新ドメインに更新済を確認。
- [x] **FFLogs OAuth Redirect URLs** から旧 URL 削除。FFLogs クライアントは 3 件 (過去 rotation 残骸の可能性、本依頼スコープ外で要調査) あり、3 件すべてから `https://raid-repository.vercel.app/api/auth/fflogs/callback` を削除。各クライアントは新ドメイン callback (+ 1 件は localhost callback) のみ残存。

## 影響しない箇所 (再確認用)

- **Discord Developer Portal**: 変更不要 (OAuth Redirect は Supabase URL を指している)
- **コード**: 変更不要 (origin はすべて動的取得)
- **Vercel 環境変数**: 変更不要 (`NEXT_PUBLIC_SUPABASE_URL` etc は外部サービス側 URL)
- **`vercel.json` / `next.config.ts`**: 変更不要 (絶対 URL 埋め込みなし)

## トラブルシューティング

| 症状 | 対応 |
|---|---|
| Login で `redirect_uri_mismatch` | Supabase Auth → URL Configuration → Redirect URLs に新ドメイン `/auth/callback` が含まれているか確認 |
| FFLogs セッション再投入時に `redirect_uri_mismatch` | FFLogs OAuth app Redirect URLs に新ドメイン `/api/auth/fflogs/callback` が exact 含まれているか確認 |
| 新ドメインで 404 | Vercel Project Settings → Domains で Production バッジ確認、deploy が新名で再ビルドされているか確認 |
| 旧ドメインアクセスで Discord OAuth 後に旧ドメインに戻ってしまう | Supabase Auth → URL Configuration → **Site URL** 自体を新ドメインに更新したか再確認 (Redirect URLs だけでは不十分) |
