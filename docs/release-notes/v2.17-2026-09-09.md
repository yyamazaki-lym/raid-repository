# v2.17 (2026-09-09)

## 🙋 自分のページ (/me) をヘッダーの人型アイコンから開けるように / ページの使い方の説明を追加

**狙い**: 実機報告「自分のページへの導線がわかりにくく、どのように使うのかも
分かりにくい」への対応。`/me` はコマンドパレット (Ctrl+K) からしか到達できず、
パレット自体を知らないと存在に気付けなかった。

**実装**:

- ヘッダー右側に人型アイコンの `<Link href="/me">` を追加。Server Component の
  素の `<Link>` なので client bundle は増えない
- ⚠ **スマホ (375px) ではヘッダーに 6 個目が入らない。** 実測でヘッダー行が
  33px はみ出した (ロゴのバージョン表記が 3 行に折り返した上でなお溢れる)。
  `sm` 未満ではヘッダーに出さず、`MainTabs` のナビ行に「自分のページ」を置く
  (あちらは `overflow-x-auto` なので溢れない)。`sm` 以上はヘッダー側だけが
  出るので、両方が同時に見えることはない
- ページ側に「何のページで、ここで何ができるのか」のリード文を追加。
  「残り BiS」「学習パス」には、値がある場合の説明行 (どこから集めた値か /
  数字の意味 / 押すとどこへ行くか) を足した。空のときは既存の空状態
  メッセージが同じ役目をするので出さない

**検証**: dev preview で実測。375px / 639px でヘッダー行の
`scrollWidth === clientWidth` (はみ出しなし) かつナビ行に「自分のページ」が
`aria-current="page"` 付きで出ること、640px / 1024px ではヘッダーのアイコンが
出てナビ行の `<li>` が `display: none` になること (二重に出ない) を
`getComputedStyle` で確認。1024px でヘッダーのアイコンをクリックして
`location.pathname === "/me"` / `h1 === "自分のページ"` まで到達を確認。

## 🎭 軽減表: ジョブを複数選べるように / コンテンツごとに違うジョブを設定できるように (層で暗黒騎士・絶で白魔道士など)

**狙い**: 実機報告「ロールは複数変わることもあるので、コンテンツごとに変更
できたり複数指定できるようにしたい」。L-8 (2026-09-08) で入れた
`native_schedule_members.job` は **1 人 1 ジョブ**で、層ごとにジョブを変える /
サブジョブも触るという固定の実態を表せなかった。

**形**:

- 新表 `native_schedule_member_jobs` (schema 5e-2 節)。1 行 =
  「この人が、このコンテンツで、このジョブ」。`category_id` が NULL の行が
  **既定** (どのコンテンツでも使う)
- ⚠ **上書きがあるコンテンツでは既定を使わない** (合併しない)。合併すると
  「4 層では暗黒騎士だけ」と言えず、上書きの意味が無くなる。この規則は
  `lib/jobs.ts` の `jobsForCategory` が正
- ⚠ **一意制約は COALESCE の式インデックス**で張った。素の
  `UNIQUE (discord_user_id, category_id, job)` では Postgres が NULL を
  互いに異なる値として扱うため**既定の行だけ重複して入る**。
  `UNIQUE NULLS NOT DISTINCT` は PG15 以降限定なので、どのバージョンでも
  同じ意味になる式インデックスにした
- ⚠ 旧 `job` 列は**残す**。移行 INSERT (idempotent) で既定の行に取り込んだ
  うえで、(a) 設定のメンバー一覧が 1 ジョブの `<select>` で表示する値、
  (b) 移行が当たっていないデプロイでの読み取り fallback として維持する。
  書き込み経路は本人 / admin の**両方が `replaceMemberJobs` を通る**ので
  食い違わない
- RLS は **policy 0 本** (service role のみ)。ジョブの割り当てを公開 anon key
  で列挙させない (`category_link_reads` 等と同じ形)

**UI**:

- 軽減表タブの絞り込みの隣は「追加の `<select>` + 選んだぶんだけチップ」。
  ⚠ 22 ジョブをトグルのチップで常時並べない (この UI が置かれる場所が
  狭いことが L-8 の出発点だった)
- `/me` に全体像 (既定の複数指定 + 上書きがあるコンテンツの一覧 + 上書きの
  追加 / 削除)。軽減表タブ側は今開いているコンテンツ 1 つしか出さない
- 「自分のロール」の絞り込みは**ロールの和集合**。「自分の担当だけ」は
  **どれかのジョブに当たる列すべて**

**あわせて直したこと**: `revalidatePath("/category", "layout")` を外した。
本番ビルドの出力で portal の全ルートが動的 (`ƒ`) と確認でき、ページ HTML の
キャッシュは存在しない一方、この呼び出しは軽減表 / ロットが使う Google
Sheets の Data Cache (`sheet-table.ts` の `unstable_cache`) を全カテゴリぶん
捨てるため、ジョブ保存のたびに次の閲覧者が Sheets への往復を待っていた。

**検証**: 合成データの一時ページで実測 (検証後に削除)。既定
= 赤魔道士 / 侍のとき「自分のロール (DPS)」でアドル + 牽制、上書き
= 暗黒騎士 / 白魔道士のとき「自分のロール (タンク / ヒーラー)」で
リプライザル + ケーラコレ + 鼓舞 (別のヒーラー列も残る)、「自分の担当だけ」で
リプライザル + ケーラコレ のみになることを確認。`/me` では既定 2 件と
上書き 1 件 (ロール: タンク / ヒーラー) が並ぶことを確認。
`check-jobs.mjs` に `rolesOfJobs` / `jobsForCategory` の検査を追加
(上書きの非合併、空配列の扱い、未知ジョブの除去、返り値の複製)。

## 🩹 出席サマリー: 期間内の pull が 1000 件で頭打ちになり、出席の突合が静かにずれていたのを修正

**狙い**: パフォーマンス調査で見つかった 1 件。最適化ではなく**バグ**で、
出席サマリーの数字が実データと合わなくなる。

**原因** (実コードで確認):

- `fflogs_fights` を `.select("report_code, start_ms").gte("start_ms", ...)` で
  期間ぶん読んでいたが、**PostgREST は既定で 1000 行が上限**
  (`lib/supabase/fflogs-fights.ts` の PAGE_SIZE コメントに実測がある)。
  90 日は週 3 日 × 40 pull で約 1,540 行なので**既に超えていた**。
  `order` も付いていなかったので、どの 1000 行が返るかも不定
- 切れた行の pull は突合から落ちるので、**「参加可と答えたのに不在」**の側に
  倒れる。エラーは出ないので画面上は正しく見える
- ⚠ 同じ関数の `fflogs_attendance_actuals` 側にも
  `.in("report_code", codes.slice(0, 300))` があり、こちらは二重の切り捨て
  だった — (a) 301 本目以降のレポートが黙って落ちる、(b) 300 本渡せても
  レポート × メンバー = 1 レポート 8 行前後なので**125 レポートで 1000 行
  上限に達する**
- #328 (明細が 1000 件で頭打ち) と同じクラスの穴が、別経路に 2 つ残っていた

**やったこと**:

- pull 側はレポート単位に畳む RPC (`fflogs_report_days`、schema 13c-4 節) に
  置換。返るのは 90 日で数十行なので上限に当たらない。⚠ **SECURITY DEFINER に
  しない** — 呼ぶのは service role だけで RLS を bypass する必要が無く、
  DEFINER にすると 15 章で塞いだ迂回路をまた作ることになる
- ⚠ **JST 暦日は SQL で計算しない**。日付の正規化は `lib/jst-date.ts` に集約
  する方針なので、RPC が返すのはレポート内の最小 `start_ms` で、暦日への
  変換は `jstYmdString` が行う
- 実績側は `report_code` を 100 件ずつに割り、各塊を `range()` で
  ページングして取り切る。順序を 2 列で固定 (順序なしの `range()` は行の
  重複 / 抜けを生む)
- 制御 (塊に割る / ページを繰る / いつ止める) は import を 1 つも持たない
  純モジュール `lib/schedule/attendance-actuals-paging.ts` に置き、
  1 ページの取得だけを呼び出し側から渡す形にした

**あわせて直った食い違い**: 以前は生行を回して「行ごとの暦日」で pull を
数えていたため、**日を跨いだレポート**の pull が `dayOfReport` の指す日とは
別の日に積まれ、その日の総 pull 数 (`dayPulls`) とメンバー別の pull 数
(`pullsBy`、レポート経由で日に結ぶ) が食い違っていた。暦日はレポート内の
最初の pull で決めるよう揃えた。

**検証**: `scripts/check-attendance-actuals-paging.mjs` を新設 (CI は
`check-*.mjs` を全部回すので自動で走る)。偽の取得関数を渡して、
250 レポート (1 塊 100 を超える) が全件返ること、1 塊が 1000 行を超えても
3,750 行すべて重複なく返ること、窓が 1000 行ずつ進むこと、読み取りエラーを
0 行に化けさせないこと、0 件なら問い合わせ 0 回になることを確認。あわせて
**呼び出し側のコードを見て** `order` 2 列と `range` があること、
`codes.slice(0, N)` の固定上限が復活していないことを構造検査で固定した。
⚠ **実 DB での再現・修正確認はしていない** (デモに練習ログのデータが無く、
共有 DB は汚さない方針のため)。上限の値と行数見積りはコード内の実測記録に
依拠している。

## 🩹 軽減表: 「自分のロール」「自分の担当だけ」に絞ると技名と時刻が消えていたのを修正

**報告**: 「自分の担当だけ、ロールだけに絞ると技名が表示されなくなる。また、
秒数が欲しい」。

**原因** (実コードで確認): 絞り込みが**担当列だけを返し、タイムライン列
(フェーズ / 時刻 / 技名) ごと落としていた**。カードの見出しは構造列
(`STRUCTURAL_HEADER_RE` に当たる列) の値から作るので、列が見えないと
`headingParts` が空になり「(無題)」だけのカードが並ぶ。時刻の列も同じ理由で
消えていたので、「秒数が欲しい」は**別の要望ではなく同じ不具合**だった。

**やったこと**: 絞り込みで**隠すのは「誰かの担当」と分かる列だけ**にした
(`columnJobs` でジョブが解決できた列)。タイムライン列やその他の列は常に残る。
表示名で当てた経路 (ジョブが解決できないシート) は、構造列と自分の列を残す。

**実測**: 合成した軽減表の一時ページ (検証後に削除) で、「自分の担当だけ」
「自分のロール」のどちらでもカードの見出しが `P1 0:12 ボス技A` のまま残り、
チップだけが絞られることを確認 (修正前は「(無題)」)。

## 🩹 日付メモ: 追加したメモが二重に並ぶことがあったのを修正

**報告**: 「メモを追加すると二重になる」。

**原因** (実コードで確認): realtime の INSERT ハンドラが **id で重複を落として
いなかった**。メモの追加後は `session-memo-popover` が realtime の取りこぼし
対策として全件再取得も走らせるため、**realtime の INSERT と再取得が競合**して
同じ行が 2 回積まれていた。共通土台の `use-realtime-table.ts` は元から id で
畳んでいて、grouped-map 版 (rawDate バケット) だけが漏れていた。

**やったこと**: 追加時に同じ id を除いてから積む (更新の分岐と同じ形)。
順序が入れ替わっても二重にならない。

## 🔍 コマンドパレットをタブと同じ行の右端へ / 自分のページのアイコンをスマホでもヘッダーに表示

**報告**: 「コマンドパレットはスケジュールやコンテンツのタブがある列で良いかも
しれない。見やすさ的には右端とかが良いか」。

いたので、`SiteHeader` 側の props は不要になり外した。

**自分のページのアイコンをどの幅でも出せるようになった**。ナビ行に置いていた
スマホ用の「自分のページ」タブは撤去 (実装が 1 つに戻る)。

人型アイコンが表示、パレットがナビ行の右端 (右端から 8px) にあることを確認。
1024px でナビ行右端のパレットを実クリックしてダイアログが開き、
「自分のページ」を含むジャンプ候補が並ぶことを確認。
## 🎲 ロット: 「欲しい人」の欄を畳めるように / コンテンツ設定で出す・出さないを選べるように (零式と絶で取得装備が違うため)

**報告**: 「欲しい人の欄は閉じられるようにしたい。これはコンテンツ設定から
表示、非表示出来ても良いかもしれない。零式と絶だと取得装備が異なるため。」

2 段構えにした。

- **読む人が畳む**: 見出しごと開閉ボタンにして、開閉を**コンテンツごとに**
  localStorage で覚える (絶では畳んで零式では開く、が続く)。
  ⚠ SSR では常に開いた状態を返し (`getServerSnapshot`)、hydration の後に
  保存値へ切り替える (`useSyncExternalStore` の想定した使い方)
- **固定として出さない**: コンテンツ設定 → タブ設定のロット行に「欲しい人」の
  チェックを追加 (`tabConfig.loot.wantMatrix`)。外すと固定の全員に出なくなる。
  既定は出す (`!== false` 判定) ので既存のコンテンツの見た目は変わらない。
  ⚠ 既定値は jsonb に書かない (無駄に太らせない)

**実測**: 合成データの一時ページ (検証後に削除) で、押すと `aria-expanded`
が false になり表が消える (`table` 1 → 0)、説明文が「閉じています (押すと
開きます)」に変わる、localStorage に `0` が入る、**リロード後も畳んだまま**
であることを確認。hydration の警告は出ていない。
