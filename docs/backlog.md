### W-19. 出席サマリー — 2026-09-08 実装

予定表ヘッダーのクリップボードアイコンから開く dialog。可視範囲は
**サーバー側で**決める (幹部 = 全員 / 本人 = 自分だけ)。画面で隠すだけでは
通信を見れば読めてしまう。⚠ **公開ランキングと streak は作らない**
(ノート 6-2)。

**突合できない日を分母に入れない**のが最重要の仕様。

- ログが 1 pull も無い日 → 「分からない」。分母に入れるとログ担当が休んだ
  日が全員の欠席に化ける。
- ⚠ **pull はあるのに参加者が 1 人も紐づいていない日も同じ扱い**
  (`unmatched`)。**dev preview で実際に「参加と回答した全員が不在」と
  表示され**、その場で仕様を直した。この状態は「全員休んだ」ではなく
  突合が効いていないサインなので、画面にそう書いて直し方 (メンバー一覧の
  「ログ名」→ 同期し直す) を添える。
- PostgREST の読み取り失敗も同様にエラーとして返す (`{ error }` を素通しすると
  0 行 = 全員不在になる)。
- 有志練習 (W-18) と中止の日も外し、件数だけ出す。

### L-6. pull 行が 2 行に折り返して読みにくい — 2026-09-08 実装

**可変にできるのは技名だけ**という前提で 3 点。

- **PT 合計 DPS はクリア pull のみ** (`reserve.metricsDps` はその日に
  クリアがあるときだけ true)。死亡数は練習 pull でも意味があるので残す。
- **技名は `max-w-[15rem]` → `min-w-0 flex-1 basis-0`**。行の中で
  `flex-1` を持つのはここだけにすること (2 つ持つと取り合いになる)。
- **動画チップを枠共有の 1 グループに畳んだ**。1 本目は時刻つき、2 本目
  以降は番号だけ (1.5rem)。どの動画も同じ pull の同じ瞬間へ飛ぶので、
  2 本目以降で要るのは「どの動画か」。**隠したリンクは無い**
  (幅が 5.5N → 4.75 + 1.5(N-1) rem)。
- 実測: DPS 有無 × 動画 0〜4 本の 8 通りで全行 33px に揃う。
  ⚠ 初出で書いた「640px までは 1 行」は**動画列 0 本で測った誤り**。
  動画 1 本 + DPS 列ありの実データでは閾値 **約 720px** だった。
- **2026-09-08 追加要望**: 動画チップから再生開始時刻を落とし、
  「マーク 1 個 + 番号」だけにした。どの動画も同じ pull の同じ瞬間へ飛ぶので
  行で要るのは「どれを開くか」だけ。幅 5.5N → 1.25 + 1.25N rem
  (1 本で 76px → 40px)。実データで**閾値が 720px → 670px 以下**に下がった。

### 設定ダイアログの折りたたみ化 — 2026-09-08 実装

実機要望「Settings が長くなってきたので、折り畳めそうなものは折り畳める
ようにする」「練習ログの通知を折り畳めるようにしたい」。共通の

  必ず畳んだ状態**になることを `getServerSnapshot` で構造的に保証している。
  真の値はモジュール内の Map で、localStorage は永続化層だけ (書き込みが
  拒否される環境で開いた直後に畳まれるのを防ぐ)。
- 矢印の回転は Tailwind の `group-open/<名前>` ではなく React の状態から
  出す。group 名は節ごとに別名が必要で、入れ子の `<details>` (FFLogs 節)
  があると名前の衝突で外側の開閉に内側の矢印が反応する。

着手時の確認どおり **PAST 詳細ログは upcoming と別 table** だったので、
`reserveSpace` のプレースホルダごと落として日程列を詰めてある (縦揃えは
table 単位でしか要らない)。upcoming 行のチップはそのまま。

### W-15. 定期枠テンプレ + 例外 — 2026-09-08 実装

設定に「定期枠」(毎週どの曜日に活動するか) を追加。選ぶと候補日の自動追加が
その曜日だけになる。候補日ダイアログに「繰り返し」(期間 + 曜日 + 時刻の一括
生成、既存日付はスキップ) を追加し、枠から外れた日には「臨時」「今回だけ」の
バッジを出す。

- 集計・判定は純関数 `src/lib/schedule/recurring-frames.ts`。
- **曜日を 1 つも選ばない = 定期枠なし**で従来どおり全日。「0 件の枠」と解釈
  すると設定をいじった瞬間に予定表が空になり、戻す導線も消える。
- **枠は曜日だけを持つ**。時刻は既存の default に任せる — placeholder の
  `raw_date` が時刻を焼き込む形で、default 変更時の遡及更新 (schema 13d 節)
  が「時刻が NULL の行」だけを対象にしているため。曜日ごとに時刻を変えたい
  ときは一括生成で明示して作る。
- 「今週スキップ」= 中止トグル、「今回だけ 22:00」= 時刻編集 popover は
  **既にあった**。足したのは「それが例外だと分かる印」。

### UI-1 + UI-2. プル・ボックス列 / カードのスパークライン — 2026-09-08 実装

- **UI-1**: 日の見出しの直下に 1 pull = 1 小箱の列 (`pull-box-row.tsx`)。
  箱に到達区間の番号を必ず書く (色だけで意味を伝えない)。**区間モデルを
  持つコンテンツ限定** — 討滅などでは書ける略号が無く色だけの列になる。
  箱 20px + 間隔 4px = ピッチ 24px (WCAG 2.5.8 の間隔例外)。**大きさと
  間隔は対で変えること。**
- **UI-2**: コンテンツカードに直近 8 週の到達度スパークライン。集計は新 RPC
  `category_progress_by_day` (schema 13c-3 節) が日 × カテゴリの数十行に
  縮約する。RPC が無い DB では線が出ないだけ。
- 到達度の式は `progressValue()` に集約し、日のバー / トレンド / 箱 /
  カードが全部同じ計算を通るようにした。

### UI-5. 区間セグメント + URL 状態同期 — 2026-09-08 実装

- 練習ログの層フィルタを 1 段のセグメントに (`segment-filter.tsx`)。
  **絶にもフィルタが付いた** (従来は層モデルにしか無かった)。

  (絞った pull で `summarize` に通し直す)。
- 軽減表の層タブを表示形式の外へ出し、iframe 側の gid も差し替える

## 運用上の注記 (実機で判明したこと)

### デモサイトのデータは `supabase/seed-demo.sql` の Section 3 (2026-09-08)

デモに直接 SQL を打たない。`seed-demo.sql` は main push で
`deploy-database-demo.yml` が demo project へ自動適用する (schema.sql と同じ
経路)。追加するときは**新しい sentinel を持つ節**を足す — 既存の
`demo_seed_applied` は 2 回目以降スキップするので、既に適用済みの demo に
対して新しい節だけを 1 回走らせるにはこれが必要。

- ⚠ **seed は CI で実行されない。** 実行時エラーはデプロイまで出ない。
  `scripts/check-seed-sql.mjs` が「列名」と「ON CONFLICT の列組」を
  schema.sql と突き合わせて CI で止める (2026-09-08 に
  `fflogs_report_videos` の主キー差し替えを見落として実際に踏んだ)。
  構文は libpg_query で別途見られる (下の注記)。
- 日付は**適用時の JST 今日から逆算**する。固定日を焼くと数か月で
  「半年前のログしか無いデモ」になる。
- デモは **native モード**。sync (外部シート) では出欠系の追加機能が
  データを入れても画面に出ない。
- 運用台帳系 (`fflogs_report_syncs` / `fflogs_notify_state` /
  `fflogs_report_blocklist`) は**意図的に入れていない**。同期の「未取得
  レポート」や通知の抑制状態を偽装すると、デモを見た人が挙動を誤解する。

### seed / schema の SQL はローカルで構文検証できる

`pip install pglast` (libpg_query = 本物の Postgres パーサ) を入れると、
`parse_sql` で外側の SQL、`parse_plpgsql_json` で `DO $$ … $$` の中身を
push 前に検証できる。**`DO` ブロックの中は SQL パーサからは不透明な文字列**
なので、両方を通す必要がある。

### 2026-09-08 に schema.sql の再実行が要る

UI-2 (コンテンツカードのスパークライン) で関数を 1 本足した
(`category_progress_by_day`、schema.sql の 13c-3 節)。再実行していない
デプロイでは**カードの線が出ないだけ**で、他の機能には影響しない。
GitHub Actions の自動反映を設定済みなら main push で当たる。

### W-5 レポート自動発見は、この固定では実質使えない

実装済みだが、2026-09-07 の実機確認で前提が満たせないことが分かった。

- **「自分のアカウントから」は Public のレポートしか拾えない**。診断パネルの
  実測で、返ってきた 12 件はすべて 2022 年以前だった (最近のレポートは
  Unlisted)。session cookie による scrape も 403。
- **「guild から自動」には前提が 2 つある**。`Report.guild` は「null なら
  ユーザーの個人ログにアップロードされたレポート」で、所属は**アップロード時に
  決まる** — Uploader でアップロード先に guild を選んでいなければ `guildID` で
  引いても 0 件で、**既存の履歴は後から移せない**。加えて一覧が Unlisted を
  返すかは未確認 (v2 のスキーマは `report(code:)` にだけ `allowUnlisted` を
  持ち、一覧の `reports()` には可視性の引数が無い)。

→ Unlisted 運用を続ける限り、確実なのは**従来の URL 貼り付け**。設定画面の
ブックマークレットでレポート一覧から URL をまとめて拾える。前提は
`docs/guides/log-runner.md` と設定画面の説明文にも書いてある。

**未実装の選択肢**: 「発見元の接続テストボタン」(同期を回さず 1 クリックで
0 件かどうかを見る)。押しても「0 件」としか出せず原因を説明できないため、
前提の明示を優先して作っていない。要望があれば作る。

### 動画オフセットは「基準の pull」を取り違えやすい

2026-09-07 に「リンクが 104 秒ずれる」報告があり、原因は**動画に最初の pull が
映っておらず** (録画開始が 82 秒後)、0:22 で始まっていたのが 2 本目の pull
だったこと。計算式は正しかった。オフセット欄の下に値の意味を実時刻で出す
表示を追加済み (`explainOffset`)。同種の報告が来たら、まずその 2 行を見てもらう。
