## 🔒 セキュリティ強化 2 件 — ログイン後リダイレクトの検証強化 + 管理者専用 DB 操作の権限チェック多重化

コード精査で見つかった予防的なセキュリティ強化 2 件 (いずれも実被害の報告はなく、多層防御の追加)。

- **ログイン後のリダイレクト先検証を強化**: Discord ログイン完了後に戻るページ (`?next=`) の検証を、最終的に解決される URL が自サイト内オリジンかどうかの確認まで含めて二重化。特殊文字を使ってサイト外へ誘導する経路 (オープンリダイレクト) を確実に防ぐ。
- **管理者専用のスケジュール時刻一括更新に DB 層の権限チェックを追加**: デフォルト開催時刻の変更時に走る「未来の候補日をまとめて更新する」DB 関数に、アプリ側の管理者チェックとは別に DB 側でも管理者判定を入れ、権限のないログイン済みユーザーが API を直接叩いても DB が拒否するようにした。手動 / 運用経路の挙動は変更なし。

**検証**: npx tsc --noEmit / npx eslint pass。リダイレクト検証は外部オリジンへ遷移しないことを確認。DB 関数の権限チェックは schema deploy 後に本番 / demo で実 ACL を確認。

## 🔒 一部の編集操作が権限なしでも「成功」と表示される問題を修正

コード精査で見つかった挙動の修正。マクロ / PT 募集テンプレート / スケジュールのメモ / スケジュール上部テキストの編集・削除・並び替えで、権限のないユーザーが操作した場合に「実際にはデータベース側で拒否されているのに、画面上は成功と表示される」ケースがあった（権限のない更新・削除は無視される一方で、エラーが返らないため成功扱いになっていた）。

更新・削除が実際に 1 件も反映されなかった場合は失敗として扱い、「権限がない可能性があります」と通知するようにした。権限のあるユーザーの操作はこれまでどおり成功する（挙動は変わらない）。

**検証**: npx tsc --noEmit / npx eslint pass。

## 🧹 上部ヘッダー / タブの固定表示位置の内部リファクタ（見た目は変更なし）

上部ヘッダー・メインタブ・コンテンツ内タブの「スクロール時に固定される位置」が、各所にバラバラの数値（102px / 110px 等）で手書きされており、ヘッダーの高さを変えると複数箇所がズレるリスクがあった。高さを 1 箇所（CSS 変数 --header-h / --nav-h）で定義し、各固定位置をそこから自動計算するように整理した。

表示上の位置・挙動は従来と同一（内部の保守性向上のみ）。

**検証**: npx tsc --noEmit / npx eslint pass / npm run build。dev preview のモバイル幅・広幅で固定位置とスクロール追従が従来と一致することを実測。

## ♿ 「視差効果を減らす」設定に対応 — 背景アニメ・点滅を停止

OS / ブラウザで「視差効果を減らす（prefers-reduced-motion）」を有効にしている利用者向けに、常時動いていた装飾アニメーションを停止するようにした。

対象: テーマごとの背景エフェクト（雪 / オーロラ / 砂塵 / 明滅 / グリッドの drift など）、ヘッダーの ONLINE インジケーターの点滅、ページ遷移待ちドットの点滅、上部タブのアンダーラインのバネ的な動き。

設定を有効にしていない場合の見た目・挙動は一切変わらない。アクセシビリティ向上（動きに敏感な利用者への配慮）と、常時アニメによる描画負荷の軽減を兼ねる。

**検証**: npx tsc --noEmit / npx eslint pass / npm run build。

## 🛠 自動取り込み・自動通知の二重化を防止（内部の堅牢性向上）

コード精査で見つかった、タイミング次第でまれに起こり得る二重処理の予防。

- **Discord 自動取り込みの重複防止**: 動画 / 攻略リンクの自動取り込みが、定期実行と手動「取り込み」が重なったときに、同じ URL を二重登録し得る構造だった。データベース側に「同じカテゴリ・種別・URL は 1 件まで」という制約を追加し、取り込み処理を重複を無視する方式に変更して確実に防ぐようにした。
- **スケジュール自動通知の重複防止**: 候補日確定の Discord 自動通知（毎時実行）が、実行が重なったときに同じ予定を二重に通知し得た。通知前に「通知済みフラグ」を先に立てて、立てられた実行だけが投稿する方式に変更（投稿に失敗した場合はフラグを戻して次回再試行）。手動のベルボタンによる再通知は従来どおり毎回送れる。

通常運用での見た目・挙動は変わらない。

**検証**: npx tsc --noEmit / npx eslint pass / npm run build。DB の制約は反映後に本番 / demo で確認。
