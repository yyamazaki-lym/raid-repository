# v2.17 (2026-09-09)

## 🙋 自分のページ (/me) をヘッダーの人型アイコンから開けるように / ページの使い方の説明を追加

**狙い**: 実機報告「自分のページへの導線がわかりにくく、どのように使うのかも
分かりにくい」への対応。`/me` はコマンドパレット (Ctrl+K) からしか到達できず、
パレット自体を知らないと存在に気付けなかった。

**実装**:

- ヘッダー右側に人型アイコンの `<Link href="/me">` を追加。Server Component の
  素の `<Link>` なので client bundle は増えない
- ⚠ **スマホ (375px) ではヘッダーに 6 個目が入らない。** 実測でヘッダー行が
  33px はみ出した (ロゴのバージョン表記が 3 行に折り返した上でなお溢れる)。
  `sm` 未満ではヘッダーに出さず、`MainTabs` のナビ行に「自分のページ」を置く
  (あちらは `overflow-x-auto` なので溢れない)。`sm` 以上はヘッダー側だけが
  出るので、両方が同時に見えることはない
- ページ側に「何のページで、ここで何ができるのか」のリード文を追加。
  「残り BiS」「学習パス」には、値がある場合の説明行 (どこから集めた値か /
  数字の意味 / 押すとどこへ行くか) を足した。空のときは既存の空状態
  メッセージが同じ役目をするので出さない

**検証**: dev preview で実測。375px / 639px でヘッダー行の
`scrollWidth === clientWidth` (はみ出しなし) かつナビ行に「自分のページ」が
`aria-current="page"` 付きで出ること、640px / 1024px ではヘッダーのアイコンが
出てナビ行の `<li>` が `display: none` になること (二重に出ない) を
`getComputedStyle` で確認。1024px でヘッダーのアイコンをクリックして
`location.pathname === "/me"` / `h1 === "自分のページ"` まで到達を確認。

## 🎭 軽減表: ジョブを複数選べるように / コンテンツごとに違うジョブを設定できるように (層で暗黒騎士・絶で白魔道士など)

**狙い**: 実機報告「ロールは複数変わることもあるので、コンテンツごとに変更
できたり複数指定できるようにしたい」。L-8 (2026-09-08) で入れた
`native_schedule_members.job` は **1 人 1 ジョブ**で、層ごとにジョブを変える /
サブジョブも触るという固定の実態を表せなかった。

**形**:

- 新表 `native_schedule_member_jobs` (schema 5e-2 節)。1 行 =
  「この人が、このコンテンツで、このジョブ」。`category_id` が NULL の行が
  **既定** (どのコンテンツでも使う)
- ⚠ **上書きがあるコンテンツでは既定を使わない** (合併しない)。合併すると
  「4 層では暗黒騎士だけ」と言えず、上書きの意味が無くなる。この規則は
  `lib/jobs.ts` の `jobsForCategory` が正
- ⚠ **一意制約は COALESCE の式インデックス**で張った。素の
  `UNIQUE (discord_user_id, category_id, job)` では Postgres が NULL を
  互いに異なる値として扱うため**既定の行だけ重複して入る**。
  `UNIQUE NULLS NOT DISTINCT` は PG15 以降限定なので、どのバージョンでも
  同じ意味になる式インデックスにした
- ⚠ 旧 `job` 列は**残す**。移行 INSERT (idempotent) で既定の行に取り込んだ
  うえで、(a) 設定のメンバー一覧が 1 ジョブの `<select>` で表示する値、
  (b) 移行が当たっていないデプロイでの読み取り fallback として維持する。
  書き込み経路は本人 / admin の**両方が `replaceMemberJobs` を通る**ので
  食い違わない
- RLS は **policy 0 本** (service role のみ)。ジョブの割り当てを公開 anon key
  で列挙させない (`category_link_reads` 等と同じ形)

**UI**:

- 軽減表タブの絞り込みの隣は「追加の `<select>` + 選んだぶんだけチップ」。
  ⚠ 22 ジョブをトグルのチップで常時並べない (この UI が置かれる場所が
  狭いことが L-8 の出発点だった)
- `/me` に全体像 (既定の複数指定 + 上書きがあるコンテンツの一覧 + 上書きの
  追加 / 削除)。軽減表タブ側は今開いているコンテンツ 1 つしか出さない
- 「自分のロール」の絞り込みは**ロールの和集合**。「自分の担当だけ」は
  **どれかのジョブに当たる列すべて**

**あわせて直したこと**: `revalidatePath("/category", "layout")` を外した。
本番ビルドの出力で portal の全ルートが動的 (`ƒ`) と確認でき、ページ HTML の
キャッシュは存在しない一方、この呼び出しは軽減表 / ロットが使う Google
Sheets の Data Cache (`sheet-table.ts` の `unstable_cache`) を全カテゴリぶん
捨てるため、ジョブ保存のたびに次の閲覧者が Sheets への往復を待っていた。

**検証**: 合成データの一時ページで実測 (検証後に削除)。既定
= 赤魔道士 / 侍のとき「自分のロール (DPS)」でアドル + 牽制、上書き
= 暗黒騎士 / 白魔道士のとき「自分のロール (タンク / ヒーラー)」で
リプライザル + ケーラコレ + 鼓舞 (別のヒーラー列も残る)、「自分の担当だけ」で
リプライザル + ケーラコレ のみになることを確認。`/me` では既定 2 件と
上書き 1 件 (ロール: タンク / ヒーラー) が並ぶことを確認。
`check-jobs.mjs` に `rolesOfJobs` / `jobsForCategory` の検査を追加
(上書きの非合併、空配列の扱い、未知ジョブの除去、返り値の複製)。
