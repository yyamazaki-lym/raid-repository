# v2.17 (2026-09-09)

## 🙋 自分のページ (/me) をヘッダーの人型アイコンから開けるように / ページの使い方の説明を追加

**狙い**: 実機報告「自分のページへの導線がわかりにくく、どのように使うのかも
分かりにくい」への対応。`/me` はコマンドパレット (Ctrl+K) からしか到達できず、
パレット自体を知らないと存在に気付けなかった。

**実装**:

- ヘッダー右側に人型アイコンの `<Link href="/me">` を追加。Server Component の
  素の `<Link>` なので client bundle は増えない
- ⚠ **スマホ (375px) ではヘッダーに 6 個目が入らない。** 実測でヘッダー行が
  33px はみ出した (ロゴのバージョン表記が 3 行に折り返した上でなお溢れる)。
  `sm` 未満ではヘッダーに出さず、`MainTabs` のナビ行に「自分のページ」を置く
  (あちらは `overflow-x-auto` なので溢れない)。`sm` 以上はヘッダー側だけが
  出るので、両方が同時に見えることはない
- ページ側に「何のページで、ここで何ができるのか」のリード文を追加。
  「残り BiS」「学習パス」には、値がある場合の説明行 (どこから集めた値か /
  数字の意味 / 押すとどこへ行くか) を足した。空のときは既存の空状態
  メッセージが同じ役目をするので出さない

**検証**: dev preview で実測。375px / 639px でヘッダー行の
`scrollWidth === clientWidth` (はみ出しなし) かつナビ行に「自分のページ」が
`aria-current="page"` 付きで出ること、640px / 1024px ではヘッダーのアイコンが
出てナビ行の `<li>` が `display: none` になること (二重に出ない) を
`getComputedStyle` で確認。1024px でヘッダーのアイコンをクリックして
`location.pathname === "/me"` / `h1 === "自分のページ"` まで到達を確認。

## 🎭 軽減表: ジョブを複数選べるように / コンテンツごとに違うジョブを設定できるように (層で暗黒騎士・絶で白魔道士など)

**狙い**: 実機報告「ロールは複数変わることもあるので、コンテンツごとに変更
できたり複数指定できるようにしたい」。L-8 (2026-09-08) で入れた
`native_schedule_members.job` は **1 人 1 ジョブ**で、層ごとにジョブを変える /
サブジョブも触るという固定の実態を表せなかった。

**形**:

- 新表 `native_schedule_member_jobs` (schema 5e-2 節)。1 行 =
  「この人が、このコンテンツで、このジョブ」。`category_id` が NULL の行が
  **既定** (どのコンテンツでも使う)
- ⚠ **上書きがあるコンテンツでは既定を使わない** (合併しない)。合併すると
  「4 層では暗黒騎士だけ」と言えず、上書きの意味が無くなる。この規則は
  `lib/jobs.ts` の `jobsForCategory` が正
- ⚠ **一意制約は COALESCE の式インデックス**で張った。素の
  `UNIQUE (discord_user_id, category_id, job)` では Postgres が NULL を
  互いに異なる値として扱うため**既定の行だけ重複して入る**。
  `UNIQUE NULLS NOT DISTINCT` は PG15 以降限定なので、どのバージョンでも
  同じ意味になる式インデックスにした
- ⚠ 旧 `job` 列は**残す**。移行 INSERT (idempotent) で既定の行に取り込んだ
  うえで、(a) 設定のメンバー一覧が 1 ジョブの `<select>` で表示する値、
  (b) 移行が当たっていないデプロイでの読み取り fallback として維持する。
  書き込み経路は本人 / admin の**両方が `replaceMemberJobs` を通る**ので
  食い違わない
- RLS は **policy 0 本** (service role のみ)。ジョブの割り当てを公開 anon key
  で列挙させない (`category_link_reads` 等と同じ形)

**UI**:

- 軽減表タブの絞り込みの隣は「追加の `<select>` + 選んだぶんだけチップ」。
  ⚠ 22 ジョブをトグルのチップで常時並べない (この UI が置かれる場所が
  狭いことが L-8 の出発点だった)
- `/me` に全体像 (既定の複数指定 + 上書きがあるコンテンツの一覧 + 上書きの
  追加 / 削除)。軽減表タブ側は今開いているコンテンツ 1 つしか出さない
- 「自分のロール」の絞り込みは**ロールの和集合**。「自分の担当だけ」は
  **どれかのジョブに当たる列すべて**

**あわせて直したこと**: `revalidatePath("/category", "layout")` を外した。
本番ビルドの出力で portal の全ルートが動的 (`ƒ`) と確認でき、ページ HTML の
キャッシュは存在しない一方、この呼び出しは軽減表 / ロットが使う Google
Sheets の Data Cache (`sheet-table.ts` の `unstable_cache`) を全カテゴリぶん
捨てるため、ジョブ保存のたびに次の閲覧者が Sheets への往復を待っていた。

**検証**: 合成データの一時ページで実測 (検証後に削除)。既定
= 赤魔道士 / 侍のとき「自分のロール (DPS)」でアドル + 牽制、上書き
= 暗黒騎士 / 白魔道士のとき「自分のロール (タンク / ヒーラー)」で
リプライザル + ケーラコレ + 鼓舞 (別のヒーラー列も残る)、「自分の担当だけ」で
リプライザル + ケーラコレ のみになることを確認。`/me` では既定 2 件と
上書き 1 件 (ロール: タンク / ヒーラー) が並ぶことを確認。
`check-jobs.mjs` に `rolesOfJobs` / `jobsForCategory` の検査を追加
(上書きの非合併、空配列の扱い、未知ジョブの除去、返り値の複製)。

## 🩹 出席サマリー: 期間内の pull が 1000 件で頭打ちになり、出席の突合が静かにずれていたのを修正

**狙い**: パフォーマンス調査で見つかった 1 件。最適化ではなく**バグ**で、
出席サマリーの数字が実データと合わなくなる。

**原因** (実コードで確認):

- `fflogs_fights` を `.select("report_code, start_ms").gte("start_ms", ...)` で
  期間ぶん読んでいたが、**PostgREST は既定で 1000 行が上限**
  (`lib/supabase/fflogs-fights.ts` の PAGE_SIZE コメントに実測がある)。
  90 日は週 3 日 × 40 pull で約 1,540 行なので**既に超えていた**。
  `order` も付いていなかったので、どの 1000 行が返るかも不定
- 切れた行の pull は突合から落ちるので、**「参加可と答えたのに不在」**の側に
  倒れる。エラーは出ないので画面上は正しく見える
- ⚠ 同じ関数の `fflogs_attendance_actuals` 側にも
  `.in("report_code", codes.slice(0, 300))` があり、こちらは二重の切り捨て
  だった — (a) 301 本目以降のレポートが黙って落ちる、(b) 300 本渡せても
  レポート × メンバー = 1 レポート 8 行前後なので**125 レポートで 1000 行
  上限に達する**
- #328 (明細が 1000 件で頭打ち) と同じクラスの穴が、別経路に 2 つ残っていた

**やったこと**:

- pull 側はレポート単位に畳む RPC (`fflogs_report_days`、schema 13c-4 節) に
  置換。返るのは 90 日で数十行なので上限に当たらない。⚠ **SECURITY DEFINER に
  しない** — 呼ぶのは service role だけで RLS を bypass する必要が無く、
  DEFINER にすると 15 章で塞いだ迂回路をまた作ることになる
- ⚠ **JST 暦日は SQL で計算しない**。日付の正規化は `lib/jst-date.ts` に集約
  する方針なので、RPC が返すのはレポート内の最小 `start_ms` で、暦日への
  変換は `jstYmdString` が行う
- 実績側は `report_code` を 100 件ずつに割り、各塊を `range()` で
  ページングして取り切る。順序を 2 列で固定 (順序なしの `range()` は行の
  重複 / 抜けを生む)
- 制御 (塊に割る / ページを繰る / いつ止める) は import を 1 つも持たない
  純モジュール `lib/schedule/attendance-actuals-paging.ts` に置き、
  1 ページの取得だけを呼び出し側から渡す形にした

**あわせて直った食い違い**: 以前は生行を回して「行ごとの暦日」で pull を
数えていたため、**日を跨いだレポート**の pull が `dayOfReport` の指す日とは
別の日に積まれ、その日の総 pull 数 (`dayPulls`) とメンバー別の pull 数
(`pullsBy`、レポート経由で日に結ぶ) が食い違っていた。暦日はレポート内の
最初の pull で決めるよう揃えた。

**検証**: `scripts/check-attendance-actuals-paging.mjs` を新設 (CI は
`check-*.mjs` を全部回すので自動で走る)。偽の取得関数を渡して、
250 レポート (1 塊 100 を超える) が全件返ること、1 塊が 1000 行を超えても
3,750 行すべて重複なく返ること、窓が 1000 行ずつ進むこと、読み取りエラーを
0 行に化けさせないこと、0 件なら問い合わせ 0 回になることを確認。あわせて
**呼び出し側のコードを見て** `order` 2 列と `range` があること、
`codes.slice(0, N)` の固定上限が復活していないことを構造検査で固定した。
⚠ **実 DB での再現・修正確認はしていない** (デモに練習ログのデータが無く、
共有 DB は汚さない方針のため)。上限の値と行数見積りはコード内の実測記録に
依拠している。

## 🩹 軽減表: 「自分のロール」「自分の担当だけ」に絞ると技名と時刻が消えていたのを修正

**報告**: 「自分の担当だけ、ロールだけに絞ると技名が表示されなくなる。また、
秒数が欲しい」。

**原因** (実コードで確認): 絞り込みが**担当列だけを返し、タイムライン列
(フェーズ / 時刻 / 技名) ごと落としていた**。カードの見出しは構造列
(`STRUCTURAL_HEADER_RE` に当たる列) の値から作るので、列が見えないと
`headingParts` が空になり「(無題)」だけのカードが並ぶ。時刻の列も同じ理由で
消えていたので、「秒数が欲しい」は**別の要望ではなく同じ不具合**だった。

**やったこと**: 絞り込みで**隠すのは「誰かの担当」と分かる列だけ**にした
(`columnJobs` でジョブが解決できた列)。タイムライン列やその他の列は常に残る。
表示名で当てた経路 (ジョブが解決できないシート) は、構造列と自分の列を残す。

**実測**: 合成した軽減表の一時ページ (検証後に削除) で、「自分の担当だけ」
「自分のロール」のどちらでもカードの見出しが `P1 0:12 ボス技A` のまま残り、
チップだけが絞られることを確認 (修正前は「(無題)」)。

## 🩹 日付メモ: 追加したメモが二重に並ぶことがあったのを修正

**報告**: 「メモを追加すると二重になる」。

**原因** (実コードで確認): realtime の INSERT ハンドラが **id で重複を落として
いなかった**。メモの追加後は `session-memo-popover` が realtime の取りこぼし
対策として全件再取得も走らせるため、**realtime の INSERT と再取得が競合**して
同じ行が 2 回積まれていた。共通土台の `use-realtime-table.ts` は元から id で
畳んでいて、grouped-map 版 (rawDate バケット) だけが漏れていた。

**やったこと**: 追加時に同じ id を除いてから積む (更新の分岐と同じ形)。
順序が入れ替わっても二重にならない。

## 📋 出席サマリーを同期式でも使えるように (character-sheets のスナップショットから突合。記録が無い日は「不在」にせず外した数を出します)

**報告**: 「出席サマリーは同期式の場合使えないか」。

**調べたこと**: 集計 (`summarizeAttendanceHistory`) は**メンバーキーで回答と
実績を突き合わせるだけ**でデータ源を問わない。同期式には
`native_schedule_attendances` が無いが、`schedule_past_sessions.attendances`
(`{"名前": "◯", ...}`) が character-sheets のスナップショットから作られた日に
入っている。つまり**名前をメンバーキーに直す層を足せば動く**。

**やったこと**:

- `getScheduleSourceMode()` で分岐し、同期式では `schedule_past_sessions` を
  読む。過去日は候補 / 中止の概念が無いので確定 (`DECISION`) として扱う
- 名前 → メンバーキーの変換を `lib/schedule/attendance-sync-symbols.ts` に
  切り出した (`@/` エイリアスを使わないので検査から単体で呼べる)。一致は
  `normalizeName` (全角/半角・空白・大文字小文字を吸収) で、催促や W-6 の
  突合と同じキー
- ⚠ **同じキーに 2 人当たったらどちらにも解決しない** (取り違えるより未解決の
  方がまし — W-6 と同じ判断)
- ⚠ **スナップショットが無い日を「全員不在」にしない。** Discord の投稿だけ
  から作られた日は `attendances` が NULL で回答が分からないので、集計から
  外して**外した日数をダイアログに出す** (`noAttendanceData`)。黙って母数を
  減らすと「休んだ」ことにされる
- 予定表の入口も `mode === "native"` から `mode !== "disabled"` に変更
  (`/me` は元から無条件に出していたので、同期式で空の集計が開ける不整合も
  これで解消)

**検証**: `scripts/check-attendance-sync-symbols.mjs` を新設 (CI は
`check-*.mjs` を全部回すので自動で走る)。表記ゆれの吸収、同名の未解決、
未登録の名前の除去、記号が文字列でない値の除去、そして**記録が無い日 (null)
と空の日 ({}) を混同しない**ことを固定した。

dev preview では `syncMode` を一時的に強制して同期式の経路が例外なく通り、
データが無いときに「ログのある活動日がまだありません」で degrade することを
確認 (一時パッチは戻した)。⚠ **実データでの突合は実測していない** —
デモは自前作成式で、同期式のスナップショットを持つデータが無い。

## 🔒 日付メモは書いた本人 (と幹部) だけが編集・削除できるように (TODO #92)

**背景**: 2026-08-05 監査の M-1 / TODO #92。日付メモの書き込みポリシーが
`USING (true)` で、**非 admin メンバー 1 人が PostgREST 直叩き 1 リクエストで
全メモを削除・改竄できた** (`DELETE .../schedule_session_memos?id=neq.<uuid>`。
ローカル PG16 で 3 件全消しを実測再現)。UI は 1 件ずつしか消せないので、
誰がやったかも残らない。

保留していたのは「メンバー全員が誰のメモでも編集できる」が意図的な製品仕様
だったため。2026-09-09 の Supabase advisor が同じ箇所を
`rls_policy_always_true` として独立に警告してきたので、**仕様を変える**方に
決めた (ユーザー判断)。

**やったこと**:

- `author_user_id` (Discord ID) を追加。⚠ 値は `app_metadata.discord_id` で、
  出欠の self-row ポリシー (7a) と同じキー。⚠ DEFAULT に subquery は書けない
  ので `auth.jwt()` を直接呼ぶ形にし、**client は列を送らなくても自分の ID が
  入る**。送ってきても INSERT の WITH CHECK が他人の ID を弾く
- ⚠ **`author_name` は所有者ではない** (localStorage 由来の表示名で誰でも
  好きな名前を書ける)。所有者判定には使わない
- insert / update / delete を **所有者 または admin** に限定。⚠ **1 アクション
  1 ポリシー**にするため、この表を 7 章の汎用ループから外して SELECT も含めて
  明示ポリシー 4 本にした (ループの admin-only と併存させると OR 評価で 2 本
  走り、Supabase lint `multiple_permissive_policies` にも当たる)
- ⚠ **既存行は `author_user_id IS NULL`** なので移行期は admin だけが触れる。
  埋め戻しはしない — `author_name` から推測すると別人の物を渡す危険がある
- UI は自分のメモ (と admin) だけ編集・削除ボタンを出す。押せるのに RLS で
  失敗する状態を作らない

**実測**: 合成データの一時ページ (検証後に削除) で、自分のメモ / 他人のメモ /
移行前 (所有者 null) の 3 件を並べ、**非 admin は編集・削除ボタンが 1 個ずつ
(自分の分だけ)、admin は 3 個ずつ**になることを確認。

## 🩹 日付メモ: 自分のメモなのに編集ボタンが出なかったのを修正 / 投稿者が記録されていない古いメモは誰でも消せるように

**報告** (実機、2026-09-09): 「自分のメモも編集できない。匿名の場合は消せる
ようにしたい」。

**原因** (実コードで確認): 上の TODO #92 で所有者ベースに変えたとき、
`viewerId` の配線が 2 箇所抜けていた。

- [`(portal)/page.tsx`](../../src/app/(portal)/page.tsx) の **sync 分岐が
  `currentDiscordId` を渡していなかった** (native 分岐だけ渡していた)。
  既定モードは sync なので、**本番では viewerId が常に null** =
  admin 以外は誰も自分のメモを編集できない状態だった
- [`schedule-past-simple.tsx`](../../src/components/portal/schedule-past-simple.tsx)
  が `viewerId` / `viewerIsAdmin` を**一切渡していなかった**。過去チップの
  popover は **admin でもボタンが出ない**

さらに `author_user_id` は 2026-09-09 に足した列なので、**それ以前のメモは
全部 NULL** (所有者不明)。配線を直しても、自分が書いた古いメモは触れない。

**やったこと**:

- 上の 2 箇所に `viewerId` / `viewerIsAdmin` を配線。sync 分岐は
  `getAuthorizedUserRoles()` を `requireDiscordMember()` に差し替えて ID も
  受け取る (React `cache()` で dedupe されるので往復は増えない)
- **所有者不明の行は「削除だけ」ログイン済みメンバー全員に開ける**
  (ユーザー決定)。⚠ UPDATE は開けない — 誰の物か分からない行の文面を別人が
  書き換えられると、履歴が黙ってすり替わる。⚠ 引き換えに「非 admin 1 人が
  PostgREST 直叩きで所有者不明のメモを一括削除できる」余地は戻る (7a-2 で
  塞いだ穴のうち旧行に限った再開放)
- 判定を [`memo-permissions.ts`](../../src/lib/memo-permissions.ts) の純関数に
  集約。UI と RLS に同じ規則を 2 重実装しない。demo のゲストは `viewerId` を
  null に正規化する (anon key は RLS に必ず弾かれるので、押せるのに失敗する
  ゴミ箱を出さない)
- 編集できない行のゴミ箱には「投稿者が記録されていないメモ・編集は不可」の
  tooltip を出す

**実測**: 合成データの一時ページ (検証後に削除) で 3 種類のメモ
(自分 / 他人 / 所有者不明) を並べ、**非 admin = 自分のメモに鉛筆+ゴミ箱・
所有者不明にゴミ箱のみ・他人のメモは無し**、**admin = 3 件とも両方**、
**ゲスト (viewerId null) = 全部無し** を確認。過去チップと sync モードの
popover に `viewerId` が届いていることは React fiber の props を実測
(`dev-bypass-discord-id` / `viewerIsAdmin: true`)。RLS 側は libpg_query
(pglast) で外側 SQL + DO ブロック + 生成される DELETE ポリシー本文を構文
検証 (ローカルに Postgres が無いため実行検証は本番/デモ反映後)。
`scripts/check-memo-permissions.mjs` が真理値表と schema のポリシー本文を
突き合わせる (壊すと赤くなることを実測)。

## 🖼️ 画像が消えている・読み込めないとき、壊れた画像ではなく「読み込めませんでした」の代替表示を出すように

**報告** (実機、2026-09-09): 「コンテンツ背景と攻略画像は表示される。画像が
ない、読み込めない場合、代替画像などにしたい」。

**原因**: URL の**形式**が壊れている場合は `safeHref` / `isSafeUrl` が弾いて
「画像URL不正」が出ていたが、**形式は正しいのに実体が取れない** ケース
(Supabase Storage から消した / imgur 側で削除 / 直リンク禁止で 403 /
Google フォトの共有期限切れ) には受けが無く、`<Image>` が壊れた img を描いて
終わりだった。alt が空のコンテンツ背景に至っては**何も出ない**ので、
「登録したのに映らない」と区別が付かない。

**やったこと**:

- [`image-with-fallback.tsx`](../../src/components/portal/image-with-fallback.tsx)
  を追加。`onError` でアイコン + 「画像を読み込めませんでした」に差し替える。
  失敗した URL 自体を state に持つ (boolean だと画像を直した後も代替表示の
  ままになる)
- 適用先: コンテンツカードの背景 (文言は出さない — カード名と重なるので
  薄いアイコンだけ) / 攻略の画像カード / アルバムのカード / 拡大表示
- 拡大表示は素の `<img>` (クリック判定の都合) なので `onError` を直接足し、
  前後送りで別の画像に移ったら復帰するようにした

**実測**: 一時ページ (検証後に削除) で、存在しない URL のカードがアイコン +
文言に、背景用 (文言なし) が薄いアイコンだけになり、**正常な画像は今まで
どおり表示される**ことを確認。コンテンツ一覧では背景 URL を一時的に壊して
実機の見た目を確認し、`git checkout` で戻した。
