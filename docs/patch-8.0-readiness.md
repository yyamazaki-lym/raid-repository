## 済み (2026-09-07)

### ① 難易度軸と進行モデルを名前から切り離した

練習ログはこれまで**カテゴリ名の文字列マッチ**だけで挙動を決めていた
(`isUltimateContent` → フェーズ管理 / `isSavageContent` → 4 層構成)。
新難易度は名称が未発表なので辞書に足せず、そのままだと新難易度のカテゴリを
作った瞬間に層クラスタが崩れた表示になる。

- `categories.difficulty_label` (自由記述 24 文字) — 練習ログのバッジ。
  空なら従来どおり名前から推測 (零式 / 絶)。
- `categories.progress_model` (`auto` / `floors` / `phases`) — 層かフェーズかの
  上書き。`auto` が既定で従来挙動。

**enum を増やしていない**のが要点。名称が判明したら
`src/lib/content-groups.ts` の辞書に足せば `auto` のままで通るようになり、
それまではコンテンツ編集で明示指定して運用できる。純関数は
`src/lib/content-model.ts`、検証は `scripts/check-content-model.mjs`。

### ② 消化チェックを 2 週ウィンドウに対応させた

- `app_settings` の `loot_window_weeks` で 1 (既定 / 7.x) か 2 を選ぶ。
  設定 UI は設定ダイアログの「週制限の消化ウィンドウ」。
- 2 を選ぶとロット管理に「今週」と「前週 (遡り)」の 2 枚が並ぶ。前週側は
  既定で畳んであり、「次のリセットまで」は出さない。
- 純関数は `openWeekStarts()` / `previousWeekStart()`
  (`src/lib/week-jst.ts`)、検証は `scripts/check-loot-window.mjs`。

**コードに「8.0 以降なら 2」と焼き込んでいない**。仕様が実機で確認できるのは
2027-01 以降なので、切り替えは人が設定で行う。

### ③ メンバー行に DC 表記

`native_schedule_members.data_center` (自由記述 20 文字)。Switch 2 版
(2026-08-04 開始) を含むクロスプレイ前提が固まり、別 DC のメンバーが混在する
固定が増えている。DC 名は運営の再編で増減するので enum にしない。

## 未着手 — 情報待ち

### ④ 立ち上げウィザード (第 1 回 C-3)

「新ティアのカテゴリ 4 層 + 軽減表 / ロット表の雛形 + 募集文 + Discord
チャンネル ID をウィザードで一気に作る」というもの。**いま作らない**判断:

- **層数が分からない。** 新難易度が何ボス構成か未発表で、「4 層」を前提にした
  雛形は外れる可能性がある。零式が従来どおり 4 層でも、新難易度が 1 ボスなら
  ウィザードの分岐が要る。
- **難易度の名前が分からない。** ウィザードが作るカテゴリ名 / スラッグに
  名称が入るので、仮名で作ると後から全部作り直しになる。
- ①〜③ と違い**スキーマに触らない**ので、後回しにしても 8.0 直前の作業量は
  増えない (ウィザードは既存の作成 API を並べるだけ)。
