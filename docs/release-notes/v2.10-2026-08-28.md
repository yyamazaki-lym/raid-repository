## 🃏 軽減表カードを「時間軸 + 攻撃 + 担当」に再構成

前回のノイズ除去だけでは計算機型の軽減表テンプレートが読める形にならなかった (実機報告:「時間軸、攻撃、軽減が分からないのであればカード化は意味が薄れる」)。カードで伝えるべき情報に絞って変換を作り直した。

- **計算列を列ごと除去**: 軽減率 (1.00)・バリア量・被ダメージ・HP バー用数値など、非空セルが全て数値の列は表示しない。誤爆防止のため、そうした列が 3 本以上ある計算機型シートでのみ発動 (ロット表の優先度列などは残る)
- **見出しを「フェーズ 時刻 技名」に合成**: PHASE / TIME / ACTION 系の構造列 (日本語表記ゆれも対応) をカードのタイトルに畳む。例:「開幕 00:00 戦闘開始!」「00:15 全体攻撃A」
- 残るセルは **「担当: 軽減スキル」だけ** になり、時系列に並んだカードがそのまま軽減表として読める
- 装飾記号の連続 (◇◇◇ 等) も除去 (単独の ○ は担当マークの可能性があるので残す)

それでも作りが特殊で読めないシートは、前回追加した「シート表示で見る」でシート埋め込みに切り替えられる。

## 🧮 残% の精度改善 + 区切り線 + 軽減表カードの整理

実機フィードバック 3 件を反映。

**「残0%」が意味を失っていた問題**: 消化 (下層の討伐) を 0% として混ぜていたため、討伐がある日は残% が常に 0 になっていた。残% を**その日の最深層での値**に変更 (例: 1〜4層前半を消化して後半 0.43% wipe なら「残0.43%」)。合わせて 1% 未満は小数 2 桁で表示し、惜しい wipe が「0.0%」に丸まらないようにした。v1 API 経由の取り込みが 100 倍値 (43 = 0.43%) を 1% 未満だけ誤変換していた穴も修正 (既存データも再同期で直る)

**到達度バーの層区切り線**: 薄すぎて見えなかった区切り線を明色化し、バーの上でも判別できるようにした

**軽減表のカード表示**: タイムライン型テンプレート (チェックボックス列・HP バー用の数値列を多数持つシート) で「(無題) / FALSE の羅列」になっていた。チェックボックス内部値 (TRUE/FALSE) や「-」等の埋め草セルを除外し、見出し列が空の行は最初の有効セル (フェーズ / 時刻) をカードの見出しに使うようにした。それでもカード化に向かないシートのために、**スマホでも「シート表示で見る」に切り替え可能**にした (選択は端末ごとに記憶)

## 🪜 4層前半/後半に対応 — 5層扱いの誤りを修正

FFLogs では最終層が前半/後半の 2 戦闘に分かれるティア (今期ヘビー級など) があり、encounter が 5 個並ぶため「5層」「1-5層」と誤表示されていた (実機報告)。

コンテンツ種別ごとに期待層数を判定するようにした: **零式は必ず 4 層構成**なので、カテゴリ名から零式と分類でき、かつティアの encounter が 5 個のときは末尾 2 つを **「4層前半」「4層後半」** として扱う。

- クリアタイルは「4層クリア」に、日ごとの層チップも「1-4層」に (前半のみ挑戦した日は「4層前半」表記)
- pull 行のバッジは「4層前半 CLEAR」(淡色) /「4層後半 CLEAR」(緑で強調)。クリア判定は従来どおり後半の討伐のみ
- 到達度バーは前半・後半をそれぞれ 1 区間として表示 (前半突破も進捗として見える)
- 絶・討滅など零式以外のコンテンツには影響なし

## 🪜 層表示の実データ対応 + 動画ジャンプの基準を pull #1 に

層対応リリース直後の実機フィードバック 2 件を反映。

**層表示が実レポートで出ていなかった問題**: 実際のレポートには同じ日のエキスパートダンジョン等、ティア外の戦闘が混ざることがあり、旧判定はそれを見て「層構成が分からない」と全体を諦めていた。**pull 数が最も多いエンカウンター群 (= そのカテゴリのティア) を自動選出**する方式に作り直し、ティア外の戦闘は一覧・集計から除外するようにした。これで「◯層」チップと層番号が実データでも表示される

**全層にクリア表記**: 討伐した pull は 1〜3 層も「◯層 CLEAR」と表示 (最終層のクリアは緑で強調、それ以外は控えめな色)。日ごとの見出しにはその日に挑んだ層の範囲 (例「1-4層」) を表示し、何層に挑戦した日かが一目で分かる

**動画ジャンプの基準を変更**: 動画オフセットの基準が「レポート開始時刻」だったため、動画で確認できる pull #1 の開始に合わせると準備時間分 (実測 +40 秒) 必ずずれた。基準を**「一覧の #1 の戦闘が動画上で始まる時刻」**に変更し、入力欄の説明もそのとおりに書き直した。⚠️ **登録済みのオフセットは基準が変わるため再入力が必要** (動画で #1 が始まる秒数をそのまま入れる)

## 🪜 練習ログの層対応 — クリア判定と到達度をティア基準に

631 pull / 54 日分の実運用フィードバックを反映した表示の作り直し。

**クリアの定義を厳密化**: 零式ティアでは消化で全層に討伐が付き「討伐」バッジが情報にならなかった。複数層のカテゴリでは **最終層 (4 層) のクリアだけ** を「クリア」として扱う。1〜3 層の討伐は pull 行に「◯層✓」として控えめに表示。絶・討滅 (単一エンカウンター) は従来どおり討伐 = クリア

**何層に挑んだかが一目で分かるように**: 日ごとの行とセッション見出しに「◯層」チップ、pull 行にも層番号を表示。層は FFLogs のエンカウンター ID から自動判定 (未挑戦の層を飛ばしても番号はずれない)

**到達度バーをティア全体基準に**: バー = (突破済み層数 + 現在層の削り) / 層数。バーに層の区切り線が入り、「3 層まで倒して 4 層を 40% まで削った」が 1 本のバーで読める

**長さの抑制**: 日ごとの到達度・セッション振り返りとも既定は直近 10 日、「残り N 日を表示」で展開

**おまけ**: クリアタイルに **最速討伐タイム** を表示 (クリア済みコンテンツの消化でタイム更新を楽しめる)

## 📋 レポート URL の貼り付け取り込み — unlisted の「発見」を人間側で補う

unlisted (限定公開) レポートは code さえ分かれば取得できるようになった (v1 経路、実機確認済み) が、**一覧 API に出ないため自動発見ができない**という穴が残っていた。FFLogs のレポート一覧を見られるのはアップロードした本人だけなので、その一覧から portal へ渡す導線を追加した。

練習ログの「URL から取り込む」ボタン → fflogs.com のレポート一覧ページを**丸ごとコピーして貼り付け** (URL を改行区切りで並べても可)。貼り付けたテキストからレポートコードを自動抽出し (検出件数をその場に表示)、1 回につき最大 25 件を取得チェーン (v2 → v1 → cookie) で取り込む。失敗した分は理由付きでその場に表示される。

これで unlisted 運用の流れは「アップロード設定を Unlisted に → 日次同期で既知レポートは自動更新、新しいレポートは URL 貼り付け or 動画リンク登録で発見」となる。

## 🔓 unlisted レポートを API で取得 — xivanalysis と同じ経路

調査により FFLogs の visibility の正確なセマンティクスが確定: **「一覧に出ない」ことと「読めない」ことは別**。unlisted (限定公開) レポートは一覧 API には出ないが、**レポートコードを直指定すれば v1 API で読める** (「リンクを知っている人は閲覧可」の API 版。xivanalysis が unlisted ログを解析できるのはこの経路)。

portal は動画リンクや日付メモの登録で既にコードを知っているので、練習ログの同期に **v1 API (code 直指定) の fallback** を追加した。v2 が permission エラーを返したレポートは v1 → session cookie の順で再試行する。**Vercel に `FFLOGS_API_KEY` (v1 Public Key) が設定されていれば、URL 登録済みの unlisted レポートの pull が取り込める**。

読めない組み合わせとして残るのは「private かつ本人以外の連携」のみ。失敗理由の文言も新しい優先順 (unlisted → API キー / private → 本人連携 or 公開設定変更) に更新した。

## 🚧 FFLogs の bot 対策強化への対応 — scrape 403 の緩和と案内の現実化

実機で「Edge 経由でも fflogs HTML scrape 403」が確認された (2026-06 の実測では通っていた経路)。FFLogs 側の bot 対策が強化されたとみられる。

- **UA の近代化**: scrape が名乗っていたブラウザが 2 年前の Chrome 124 のままで、古い UA + データセンター IP の組み合わせが bot 判定されやすくなっていた。現行版に更新
- **fights 取得を XHR として自然な形に**: pull データの JSON エンドポイントを「ページとして直接開く」風のヘッダーで取りに行っていたが、実ブラウザにはない挙動でそれ自体が bot シグナルだった。実ブラウザと同じ XHR ヘッダー (Referer = レポートページ、Sec-Fetch-Dest: empty 等) に変更
- **案内の現実化**: 「cookie を登録すれば取れます」と断言していた文面を改め、cookie は「試みる」手段、**確実なのはレポートの Public 化** (アップローダの既定公開設定を Public にすれば以後は全自動) であることを診断パネルと失敗理由の両方に明記

ヘッダー更新で 403 が解消するかは FFLogs 側の判定次第 (TLS 指紋で弾いている場合は効果なし)。解消しない場合の運用は Public 化が唯一確実な経路になる。

## 🛠 private 取得の経路修正 (Edge 経由) + PC でもカード表示

実機の続報 3 件への対応。

**cookie fallback が効かなかった問題**: 前回入れた「session cookie で private レポートの pull を取得する」fallback は、Vercel の Node サーバーから FFLogs へ直接アクセスしていたため、Cloudflare の bot 判定 (恒常 403) に弾かれて一度も成功していなかった。レポート一覧の取得が以前から使っている **Edge 中継 (scrape-proxy)** を fights 取得にも通すよう修正。cookie を登録して「ログを同期」を押せば private レポートの pull が入るようになる (ローカル開発では従来どおり直接アクセス)。

**unlisted も API では読めない**: 実機確認により、限定公開 (unlisted) レポートも v2 API では取得できないことが判明。「unlisted にすれば取り込める」という誤った案内を撤去し、対処は「session cookie の登録」または「アップロード本人の OAuth 連携」の 2 つに整理した。

**カード表示を PC でも確認できるように**: 軽減表 / ロットの読み取り専用カードはスマホ幅専用で、PC からは存在自体が分からなかった。PC にも「カード表示で見る ⇄ シート表示に戻す」の切替ボタンを追加 (選択は端末ごとに記憶)。スマホは従来どおり常にカード。

## 🔐 非公開 (private) レポートへの対応 — 絶などのログが取り込めない問題

実機で「ヘビー級以外が同期できない」原因を特定した。FFLogs v2 API は **private レポートをアップロード者本人の連携でしか読めず**、固定メンバーが private でアップしたレポート (絶竜詩など) が「did not grant permission」で全滅していた。

対応:
- **session cookie fallback**: 設定で FFLogs の session cookie を登録している場合、private レポートも取得を試みる (レポート一覧の取得に既に使っている cookie と同じもの。新しい設定は不要)
- **失敗理由を日本語化**: 「非公開 (private) レポートのため取得できません — アップロードした本人の FFLogs アカウントで連携するか、公開設定を unlisted / public にすると取り込めます」と原因と対処が分かる文面に (既存の英文エラーも表示時に変換)
- **恒久失敗のリトライ抑制**: private による失敗は再試行しても結果が変わらないため、日次の自動同期では再試行せず取得枠 (40 件/回) を新規レポートに回す。手動の「ログを同期」ボタンは cookie 登録直後に押される想定なので毎回再試行する
- **未割当の失敗も表示**: 取得に失敗して zone も分からないレポートは今までどのコンテンツのページにも出ず「同期したのにログが出ない」理由が見えなかった。「取り込めていないレポート」欄に「コンテンツ未割当」バッジ付きで表示し、レポートコードから FFLogs へ直接飛べるようにした

## 📈 練習ログタブ — pull ごとの記録と振り返り

FFLogs に溜まっている pull 単位のデータを portal 内で読めるようにした。コンテンツごとに「練習ログ」タブが増える。

**進捗**: 総 pull 数 / 練習日数 / 最深到達 (フェーズと残 HP%) / クリア回数を上部にまとめ、その下に日ごとの pull 数バーを並べる。記録を更新した日には旗アイコンが立つので、「先週より進んでいるか」がスクロールなしで分かる。

**振り返り**: 日付を開くとその日の pull 一覧が出る。各 pull から (1) FFLogs のその pull、(2) XIVAnalysis のその pull の解析、(3) 動画のその瞬間 に 1 クリックで飛べる。動画へのジャンプは、管理者が「レポート開始が動画の何秒地点か」を 1 回入力した report でのみ有効 (それ以降その日の全 pull の時刻は自動計算)。

データは日次の FFLogs 同期 (深夜) で取り込まれる。管理者は「ログを同期」ボタンで即時実行もできる。どの pull がどのコンテンツかは、既存の「動画に FFLogs URL を紐づける」設定と、コンテンツ編集の FFLogs zone ID から判定する (新しい自動マッチは足していない)。

**表示しないもの**: 個人ごとの DPS やランキングは集計も表示もしない。出すのは PT としての到達度だけ。

## 🎲 今週の消化チェックと最適装備 (BiS) リンク

ロットタブの上に 2 つのパネルを追加した。
