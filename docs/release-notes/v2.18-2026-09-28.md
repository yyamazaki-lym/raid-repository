# v2.18 (2026-09-28)

## 🔁 Discord 取り込みで動画が入ったら、Logs 同期も続けて自動で実行するように (翌朝 04:00 を待たずにログが付く)

**狙い**: 実機要望「Logs 連携のログ同期を動画取り込み後に自動で行いたい」。動画の
Discord 取り込み (cron JST 01:00 / メンテナンスメニューの手動実行) と Logs 同期
(FFLogs ⇔ 動画のリンク + pull 取り込み、cron JST 04:00) が別々に動いており、
手動や日中に取り込んだ動画には翌朝 04:00 まで Logs が付かなかった。

**実装**:

- 同じ実行の中では続けない。取り込み本体に、リンク (時間予算 240s) と pull 取り込み
  (時間予算 120s) を足すと Vercel の上限 300s を超えるため、必ず別の実行に分ける。
  共通部品は `src/lib/server/logs-auto-sync.ts` にまとめた
- 手動: `importDiscordNow` が「動画が 1 件以上入り、トグルが OFF でない」ときに
  `logsAutoSync: true` を返す。メンテナンスメニューはそれを受けて
  `linkFflogsReports` → `syncFflogsFightsAfterImportAction` を順に呼び、
  進み具合をトーストで出す。同期に失敗しても取り込みは成功扱いのまま
- cron: `/api/cron/import-discord` が同じ条件で `/api/cron/fflogs-sync` を
  `Authorization: Bearer ${CRON_SECRET}` 付きで起動する。完了は待たず、10s で
  打ち切る (打ち切っても起動済みの実行は止まらない)。宛先は Host ヘッダではなく
  `VERCEL_PROJECT_PRODUCTION_URL` で固定する (secret を載せるため)
- 自動同期の pull 取り込みは cron と同じ条件にし、恒久失敗 (private レポート) は
  再試行しない。手動の「ログを同期」ボタンは従来どおり再試行する
- ON/OFF は新設せず、既存の日次自動連動トグル (`fflogs_cron_enabled`) に従う。
  トグルの説明文に「取り込み直後にも実行」を追記した
- JST 04:00 の同期 cron は取りこぼし拾いとして残す
