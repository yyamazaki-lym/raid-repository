## 🕛 PR — 過去簡易チップの past 判定を詳細テーブルと同じ「JST 今日 0:00」に統一

**経緯**: ユーザー報告「過去日程で詳細には入るが簡易には入らない場合がある」。過去簡易チップ (日付チップ) は `Date.now() - 6h` (NextSessionCard の STILL_RELEVANT_MS と同じグレース) を past 判定に使っており、詳細テーブル (`splitSessions`、TODO #80 で「JST 今日 0:00」に確定) と cutoff が別実装だった。このため開催翌日の JST 0:00〜開始時刻+6h (21:00 開催なら深夜 0:00〜3:00) の間、その日程が詳細テーブルには出るのに簡易チップには出ない不一致が発生していた。

**変更内容**:
- [src/lib/schedule/jst-cutoff.ts](src/lib/schedule/jst-cutoff.ts) 新設: 「JST 今日 0:00」を UTC ms で返す `jstTodayStartMs()`。cutoff 計算をここに一本化し、片方だけ将来変更されて再び食い違うのを防ぐ
- [src/components/portal/schedule-list.tsx](src/components/portal/schedule-list.tsx): `splitSessions` 内のインライン JST 計算をヘルパー呼び出しに置換 (値の意味論は無変更)
- [src/components/portal/schedule-past-simple.tsx](src/components/portal/schedule-past-simple.tsx): cutoff を `Date.now() - 6h` から `jstTodayStartMs()` に変更し、モジュールローカルの `STILL_RELEVANT_MS` を削除

**挙動変化 (許容済)**: 開催翌日 0:00〜開始+6h の深夜帯は、NextSessionCard (6h グレースで前日分を「次回」に残す) と簡易チップの両方に同じ日程が出るが、これは詳細テーブルが元々持っていた重複と同じ挙動。また時刻未入力の日付 (JST 00:00 扱い) が当日朝 6:00 から簡易だけに先行表示される逆方向の不一致も解消。

**触らない範囲**: `pickNextDecision` の 6h グレース (NextSessionCard の「次回」維持) / `mergeStoredPastSessions` のサーバ側 6h 検証ガード (データ採用判定、表示 cutoff とは独立) / 簡易チップの直近 7 件打ち切り (`SIMPLE_LIMIT`) と DECISION のみ表示の仕様。

**検証**: `npx tsc --noEmit` PASS / `npm run build` ✓ / dev preview で簡易チップ 7 件 (5/30〜4/30) と詳細テーブル past 側の先頭 7 件の日付が完全一致 + console error なしを実測。深夜帯固有の境界挙動は時刻依存のため実機未観測だが、cutoff が同一関数の同一値になったことで定義上不一致は起きない。
