## 🧭 PR — TODO #90: SubTabs の active tab がモバイル初期表示で画面外に出るケースを解消

**経緯**: TODO #7 (2.6 / 2026-06-10) のモバイル幅監査で見送り所見として記録した項目をユーザー承認で起票。SubTabs のタブ列は `overflow-x-auto` (scrollbar 非表示) で常に `scrollLeft=0` から表示されるため、375px では右端寄りの「動画」「マクロ」を開いた時に active tab が画面外となり、現在地が視認できなかった。

**変更内容** [src/components/portal/sub-tabs.tsx](src/components/portal/sub-tabs.tsx): `useEffect` (`pathname` 依存) で active tab (`data-active="true"`) がタブ列の可視範囲から見切れている時だけ `ul.scrollLeft` を直接代入して中央へ寄せる。
- **見えていれば no-op**: 既に可視なら一切動かさない (タブクリック時の無駄な視覚ノイズ回避)。overflow しない desktop も常に no-op
- **`scrollIntoView` 不使用**: 祖先要素の縦スクロールまで動かすため、既存の stuck/unstuck hysteresis 機構 (TODO #56/#58) や Link onClick の `window.scrollTo(top)` (TODO #58 part2) と干渉しうる。`scrollLeft` 代入は横軸のみで完全独立

**触らない範囲**: stuck/unstuck 機構 / ActionSlotTarget / framer-motion の `layoutId` 下線 / タブの描画・サイズは完全無改修。新規依存なし (既 import の useEffect/useRef のみ)。

**検証**: `npx tsc --noEmit` PASS / `npm run build` ✓ / dev preview 375px でマクロタブ直アクセス時に `scrollLeft > 0` + active tab 可視、軽減表 (先頭) タブでは `scrollLeft = 0` のまま、desktop 幅でも no-op を確認。
