## ⚡ 初回表示を軽く: 設定ダイアログと更新履歴を「開いた時」に読む

「動作に問題を起こさず、高速化・軽量化できるか」への対応です。

これまで、どのページを開いても**設定ダイアログ本体と更新履歴の全文** (合わせて約 470 KB、圧縮後でも約 150 KB) を毎回ダウンロードしていました。ヘッダー右上の歯車ボタンを表示するために、押されるかどうかに関係なく中身まで先に取りに行っていたためです。更新履歴の本文は文章量が増え続けていて、この大半を占めていました。

**歯車ボタンは見た目だけを先に出し、押した時 (またはマウスを載せた時) に中身を取り寄せる**ようにしました。ボタンはサーバー側の描画に含まれるので、以前あった「ボタンが一瞬遅れて現れる」も無くなります。更新履歴の本文は、ダイアログの中で「更新履歴」を押した時に初めて読み込みます。

見た目・操作・表示内容は変わりません。FFLogs 連携から戻ってきた時に設定が自動で開く挙動もそのままです。初めて押した時だけ、回線状況によっては開くまでにわずかな待ちが出ることがあります。

## 🔔 FFLogs 連携から戻った時の通知が出ないことがあったのを修正

FFLogs の認証を終えてポータルに戻った直後、「認証に成功しました」「FFLogs OAuth: …」の通知が**表示されないことがありました**。設定ダイアログは開くのに、結果だけが分からない状態です。

通知の表示部品は初回表示を軽くするために少し遅れて読み込まれるのですが、その到着より先に通知を出そうとすると**そのまま捨てられていた**のが原因です (以前からの不具合で、条件次第で 3 回に 0〜1 回しか出ていませんでした)。

表示部品の準備ができてから通知を出すようにしました。ダイアログが自動で開くことと、URL から認証用の文字列が消えることは変わりません。

## 🖱 読み込み直後に「ルール」などのボタンへ白い枠が付くのを修正

「スケジュールページを更新 (再読み込み) するとルールボタンに白い枠が出る。他の場所を押すと消える」への対応です。

**原因**: 手書きポップアップ共通フック `src/lib/use-dismissable-popup.ts` の「閉じた直後にフォーカスをトリガーへ戻す」effect が、`open === false` なら無条件に走る実装だったため、**初回 mount** (open=false / activeElement=body) でもトリガーへ `focus()` していました。読み込み直後でユーザー操作が無い状態の script focus にはブラウザが `:focus-visible` (白い枠) を付けます。スケジュールの「ルール」、コンテンツ一覧の「メンテナンス」(admin)、日付メモのポップオーバーが同じフックを使っており、ページ内で最後に mount した方に枠が付いていました。

**修正**: 直前の `open` を ref で覚え、true → false の遷移のときだけフォーカス復帰を行うようにしました。閉じた後にトリガーへ戻す従来の動きは変わりません。

**検証**: dev (DEV_AUTH_BYPASS) で `/category` を開いた直後の `document.activeElement` を Playwright で確認。修正前は `button[aria-label="メンテナンスメニューを開く"]` で `:focus-visible` が true、修正後は `body`。

## 📝 更新履歴の本文を docs/release-notes に移動 (画面表示は変わりません)

更新履歴の各 part には `title` と `body` があり、画面 (設定 → 更新履歴) に出るのは `title` だけでした。`body` は開発者向けの記録 (狙い / 実装 / 検証) で、アーカイブ 630 KB の 9 割以上を占めていました。

**変更**:
- 全 37 エントリ / 308 part の `body` を `docs/release-notes/v<version>-<date>.md` へ移動 (`# v<version> (<date>)` の下に part ごとの `## <title>` + 本文)。移行はスクリプトで行い、(a) TS の結合配列が「元データから body を消したもの」と一致、(b) md を読み戻した見出し・本文が元の title / body と一致 (308/308) を確認
- `ReleasePart` から `body` を削除 (残っていれば tsc が落ちる)
- `scripts/check-changelog.mjs` に md の検査を追加: parts を持つ全エントリに md があり、`##` 見出しが TS の title と順序込みで一致、対応するエントリの無い md が無い
- 書き方を `docs/release-notes/README.md` に、追加手順を `changelog-meta.ts` の 5 点セットに記載。`.claude/done.md` / `.claude/HANDOFF.md` の参照先も更新

**効果**: `changelog-archive.ts` 630 KB → 37 KB (source)。「過去の更新履歴を見る」押下時の取得 571 KB → 数十 KB。画面の表示内容・並び順は変わりません。

**デメリット (承知の上で採用)**: title は TS、本文は md と書く場所が 2 つになる。欠落と見出しのずれは CI で検出できるが、本文の内容そのものは検査できない。将来 UI に本文を出したくなった場合は md を読む仕組みが別途要る。
