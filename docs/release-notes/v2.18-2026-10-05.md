## 📆 練習ログ: 日程に紐づいたレポートの日付が「2026/10/04(日) 21:30~0:00」の形で入り、同じ日が 2 つに割れる・並び順がずれる・出席の自動突合が保存されない・週のまとめに入らない・毎回取り直す、となっていたのを直した (日付を YYYY-MM-DD にそろえ、保存済みの行も書き換え)

### 狙い

取り込み〜紐づけ〜解析の精査 (3)。`fflogs_fights.session_date` (練習ログの「日」) は、日程の Logs (`schedule_past_session_logs` / `native_schedule_session_logs`) から付いたレポートだと日程の rawDate (`2026/10/04(日) 21:30~0:00`) がそのまま入り、それ以外は `2026-10-04` だった (本番で実測)。形が混ざると:

- **出席の自動突合が黙って失敗する**: 保存先の CHECK が `char_length(session_date) <= 20` で、rawDate は 24 文字。1 行でも当たるとその回の保存が丸ごと失敗し、画面には何も出ない
- 取り直しの判定 (`isRecent`) が日付を読めず「直近」扱いになり、日程に紐づいたレポートを**毎回全部取り直す** (取得枠を食う)
- 練習ログの日が割れる (rawDate が 2 つ / rawDate と YYYY-MM-DD が混ざる)。並び替えは文字列比較なので、rawDate の日が同じ年の YYYY-MM-DD の日より上にまとまり、時系列・記録更新の旗・トレンド・カードのスパークラインがずれる
- 週のまとめ (今日入れた) は YYYY-MM-DD で範囲を比べるので、rawDate の pull が週から落ちる

### 実装

- `src/lib/session-date.ts` (新規・純関数): rawDate の先頭の日付 (開催日) を `YYYY-MM-DD` に。書式のゆれ (月日 1 桁 / 括弧の前に空白) も受け、存在しない日・読めないものは null
- 書き込み: 日程の Logs から付けるときと、台帳から読む日付 (取り直しの判定) でそろえる (`fflogs-fights.ts`)。出席の突合の保存も同じ値が流れる
- 読み取り: `fightDate` でもそろえる (保険。読めなければ開始時刻の JST 暦日)
- **schema.sql 6b-12: 保存済みの行を一度だけ書き換える** — `fflogs_fights.session_date` / `fflogs_report_syncs.session_date` / `fflogs_attendance_actuals.session_date` / `fflogs_attendance_unresolved.last_session_date` のうち rawDate の形の行だけ (冪等)。日付として読めない行は止めずに飛ばす (NOTICE に残す)

### 検証

- `scripts/check-session-date.mjs` (新規): そろえ方 (rawDate / 月日 1 桁 / 空白 / YYYY-MM-DD / 存在しない日 / 読めないもの)、`fightDate` (22:00 と 21:30 が同じ日になる)、配線、schema の節
- `check-logs-weekly-summary` に「日付が rawDate の形でも週に入る」を追加

## 🔘 出欠の催促: Discord のボタンで回答できるように (自前作成式・既定 OFF)。催促メッセージの予定ごとのボタンを押すと、その人の出欠がポータルに入る。使うには Discord 側の設定とサーバーの公開鍵が要る

### 狙い

2026-10-01 全体精査の F-6 の W-21 (調査ノート第 4 回「Discord ボタンで ○×△ 回答」)。Web を開かない人の出欠の入力を減らす。2026-10-05 のユーザー確認: Bot のアプリはポータル専用 (Interactions Endpoint URL を設定すると、そのアプリのボタン・スラッシュコマンドがすべてポータルに届くようになるため)。

### 仕組み

- ボタンが押されると、Discord が Bot のアプリに設定した **Interactions Endpoint URL** (`/api/discord/interactions`) へ POST する。要求に付く **Ed25519 の署名をアプリの公開鍵 (`DISCORD_PUBLIC_KEY`) で検証してから**中身を信じる。公開鍵が未設定なら全部 401 (fail-closed)。署名の時刻が 5 分より古い / 先の要求も弾く (使い回し対策)
- 押した人の Discord ユーザー ID は署名された要求の中にあり、ポータルのメンバー (`native_schedule_members.discord_user_id`) と突き合わせる。**書くのは押した本人の行だけ**。自前作成式でない・予定が無い / 中止・有効なメンバーでない・記号が**いまの**選択肢に無い (送った後に選択肢が変わった) ときは書かない
- 返事は押した本人にだけ見える (ephemeral)。出られない記号に変えたら遅刻 / 早退の予定時刻は消す (Web の保存と同じ)、全員回答で自動確定する設定 (既定 OFF) も同じく見る
- ボタンの値 (`custom_id`) は `att1:<予定の ID>:<記号>`。何番目の選択肢かではなく記号そのものを持つ

### 実装

- `src/lib/discord-interactions.ts` (新規・純関数): 署名の検証 (WebCrypto の Ed25519)、`custom_id` の組み立てと読み取り、ボタンにする選択肢 (未回答の印を除いて 5 つまで)、ボタンの並び (予定ごとに 1 行・5 行まで、予定が 2 つ以上なら「10/07(水) 絶 ○」のように予定の名前を付ける、○ は緑 / × は赤)、押した人の ID、本人だけの返事
- `src/app/api/discord/interactions/route.ts` (新規): 生の本文を取る → 署名を検証 → JSON として読む。PING には PONG。proxy ではログインの対象外 (署名で認証) にし、署名より前で連打を抑える (60 回 / 分)
- `src/lib/server/discord-attendance.ts` (新規): 確かめてから service role で upsert
- 出欠の催促: 自前作成式の予定に予定の ID を持たせ、設定「Discord のボタンで回答」(既定 OFF) が ON かつサーバーに公開鍵があるときだけボタンを付ける。どれかが欠けたら従来どおりボタン無しで送る。設定画面に公開鍵が無い旨を出す

## 🗓 スケジュール: 開催時刻を後から変えた日 (22:00 → 21:30 など) が、過去の日付チップ・詳細表に2 つずつ並んでいたのを 1 つにまとめた (動画・Logs・メモは残した方に寄せる。出席サマリーも同じ日を 2 回数えない)

- 出席サマリー (同期式): 同じまとめ方で開催日を数える (2 回数えて出席率が下がっていた)。あわせて、過去ログから除外した日 (実施しなかった日) を数えないようにした (表示側は除外済みだった)
