# v2.18 (2026-10-10)

## 🩹 練習ログ: ワイプ原因の技名が英語のまま残ることがあったのを直した (技名を引く XIVAPI は、問い合わせに無い技 ID が 1 つでも混ざると丸ごと 404 を返すため、無い ID を除いて引き直す)

### 狙い

実機報告: 絶もうひとつの未来の練習ログで、ワイプ原因の技名が `BRD ← Twin Silence` のように英語のまま出ていた。「ログを同期」を押すと一部だけ日本語になる。

技名を表示言語で引く仕組み (L-7、2026-09-08) は入っていて、手元の dev では同じ関数が日本語名を返す。本番の実行ログ (Chrome で練習ログを開いた直後の Vercel runtime logs) に `[xivapi] Action sheet fetch failed — 技名は元のまま: Error: XIVAPI Action sheet 404` が、ページ描画 (`localizeWipeAbilities`) と同期 (`attachBothAbilityNames`) の両方で出ていた。

curl で確かめると、XIVAPI v2 の `sheet/Action?rows=…` は**シートに無い行 ID が 1 つでも混ざると要求全体を 404** にする (`{"code":404,"message":"not found: the Excel row Action/99999999:0 could not be found"}`)。FFLogs の `ability.guid` には Action シートに無い ID が混ざることがあり、そのバッチ (最大 50 ID) の他の技まで全部名前が付かなかった。同期で一部だけ日本語になったのは、たまたま無い ID を含まなかったバッチだけ通ったから。

### 実装

- `lib/xivapi-actions.ts`: 404 本文から無い行 ID を取り出す純関数 `parseMissingRowId` を足した (`Action/<id>[:<sub>] could not be found` の形。別シートや形が違う本文は null)。引き直しの上限 `XIVAPI_MAX_MISSING_RETRIES = 5` (1 回 1 往復なので描画中の締切 2.5 秒に収まる程度)
- `server/xivapi-action-names.ts` の `cachedBatch`: 404 なら本文から無い ID を取り出して除き、上限回数まで引き直す。除いた ID は「シートに無い」(null) として Data Cache に覚える (次からは引かない)。本文の形が違う / 上限を超えた / 404 以外は従来どおり投げる (Data Cache に失敗を覚えさせない)

### 検証

- curl で XIVAPI の実挙動を確認: `rows=40194,99999999` → 404 (本文に `Action/99999999:0`)、`rows=40194` 単独 → 200 (`閑寂の双剣技`)。手元のネットワークからは User-Agent の有無に関わらず 200
- dev の一時 route で実関数 `resolveActionNames` を叩いた: 無い ID を 2 つ混ぜた 5 ID のバッチで、修正前は 404 で 0 件、修正後は 3 件 (閑寂の双剣技 / バウショック / 閑寂の双剣技、en は Twin Silence / Bow Shock / Twin Silence) が付く (1.8 秒 = 3 往復 × 2 言語)。route は検証後に削除
- `check-xivapi-actions.mjs` に 404 本文の解釈 (実応答の形 / サブ行無し / 別シートは拾わない / 形違いは null / 上限) を足した。`tsc` / `eslint` 緑
- 本番は merge 後に Chrome で練習ログを開いて、runtime logs に 404 が出ず技名が日本語になることを確認する (保存済み pull は描画時に引くので、同期し直さなくても直る)

## 🎬 練習ログ: 同じ日に 2 本以上入った動画 (Discord 取り込みと YouTube 再生リスト取り込みなど) を、全部そのレポートに自動で紐づけるようにした。「この動画を外す」は動画側の Logs リンクも外す (外さないと次の同期で戻るため)

### 狙い

実機報告: 同じ日に Discord 取り込みと YouTube 再生リスト取り込みの両方で動画が入ったのに、練習ログのセッションには片方 (「動画 1」) しか紐づかない。動画タブでは両方に FFLOGS / ANALYSIS バッジが付いている (= `logs_url` の橋渡しは両方に入っている)。

原因は 2026-10-02 の `seedReportVideosFromLinks` の設計 — 「レポートに動画オフセット行が 1 本でもあれば 2 本目は足さない (人が決めた並びを崩さないため、2 本目は『動画を追加』で)」。再生リスト取り込み (同じ日に入った機能) によって、同じ日の動画が毎回 2 本入る運用になり、2 本目が毎回手作業になっていた。10-06 / 10-09 のセッションとも「動画 1」だけなのを本番で確認。

### 実装

- `seedReportVideosFromLinks`: 候補を「`logs_url` の指すレポートに、その URL の行がまだ無い動画」に広げた。既存行 (秒数・表示名・並び) は触らず、新しい行は既存の `sort_order` の末尾に投稿順で付ける。同じレポートに 2 本足すときも番号が重ならないように採番する
- `offsetsFromRecordingTitles`: 1 レポートに複数の候補が来るので、キーを (レポート + 動画 URL) にした。同じレポートの動画は同じ pull #1 を基準に、録画開始の時刻だけ動画ごとに読む
- `deleteReportVideoAction` (「この動画を外す」): 動画側の `logs_url` がそのレポートを指していれば外す。外さないと seed が次の同期で同じ動画を戻してしまう。確認ダイアログの文言 (ja / en) にその旨を足した

### 検証

- `check-video-sync.mjs` の配線検査を新しい形 (キーが `c.key` / 末尾に採番 / 外すときに logs_url を外す) へ更新。`tsc` / `eslint` / `check-ja-strings` / `check-ui-safety` 緑
- 本番は merge 後に「ログを同期」で 10-06 / 10-09 のセッションに「動画 2」が付くことを Chrome で確認する
