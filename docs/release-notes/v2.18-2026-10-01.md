# v2.18 (2026-10-01)

## 📱 練習ログ: スマホ幅でセッション振り返りの日付が「2026-…」と省略されて読めなかったのを、「09-04」の形で出すように

**狙い**: 2026-10-01 の全体精査 (U-1) で、dev preview を 375px 幅で計測して
見つけた不具合。練習ログの「セッション振り返り」の行見出しで、日付の列が
`min-w-0 flex-1 truncate` だったため、右側の統計 (pull 数 / 戦闘時間 / 死亡数 /
層 / 結果) に押されて 69px まで縮められ、「2026-…」と省略されていた
(計測: 中身 112px / 表示 69px)。日付はこの行の唯一の識別子なので、どの日の行か
分からなかった。

**実装** (`src/components/portal/logs/day-row.tsx`):

- 日付の列を縮めない (`shrink-0`、`truncate` / `min-w-0` を外す)
- `sm` 未満では、同じページの「日ごとの到達度」と同じ月日 (`09-04`) を出す。
  `sm` 以上は従来どおり年付き (`2026-09-04`)
- 読み上げには常に年付きを渡す (`sr-only sm:not-sr-only`)
- `DaySummary.date` は JST の `YYYY-MM-DD` 固定 (`fflogs-progress.ts`) なので、
  月日は `slice(5)` で取れる

**検証**: dev preview (375px) で日付列の中身と表示幅が一致し (69px / 69px)、
「09-04」が見えることを確認した。1280px では年付きだけが出る (月日の span は
`display: none`)。行の配置は修正前と同じ。

## 🔄 スマホを背面から戻したとき・回線が戻ったときに、日付メモ・リンク・マクロなどを取り直すように (切れている間の変更が出ないままだった)

**狙い**: 2026-10-01 の全体精査 (U-5)。Supabase Realtime は、切れている間に
起きた変更を後から再送しない。購読フックは購読エラー (CHANNEL_ERROR /
TIMED_OUT / CLOSED) のときだけ 1 回取り直していたので、エラーにならずに静かに
再接続した場合 (スマホの背面・PC のスリープ・回線断) は、次に誰かが変更するか
リロードするまで古いまま表示し続けた。`visibilitychange` / `online` を見ている
コードは 0 件だった。

**実装**:

- 共通フック `useRealtimeChannel` に `onResume` を足した。`online` では必ず、
  タブが見えるようになったときは **30 秒以上隠れていた場合だけ**呼ぶ
  (タブを一瞬切り替えただけで全購読が SELECT し直すのを避ける)。判定は純関数
  `src/lib/realtime-resume.ts`
- `useRealtimeTable` (カテゴリ / リンク / アルバム / マクロ / ウェイマーク /
  募集テンプレ) と日付メモのフックが、`onResume` で全件を取り直す

**検証**:

- `scripts/check-realtime-resume.mjs` で判定の境界と、フックの配線 (聞く / 外す /
  取り直す) を固定した。修正前のコードに当てると 12 件 FAIL する
- dev preview の TOP で、`online` を発火するとカテゴリ・日付メモ (2 本)・
  募集テンプレの 4 本が取り直すことをネットワークで確認した。0.2 秒だけ隠した
  ときは 0 本、31 秒隠した扱いにすると 4 本

## 👥 同期式でも設定にメンバー一覧を出すように (自分のページ・BiS・欲しい人行列・出席サマリーの本人判定に使う表で、これまで登録できなかった)

**狙い**: 2026-10-01 の全体精査 (F-1) で見つけた抜け。設定の「メンバー」節
(`native_schedule_members` の登録画面) は自前作成式のときしか出なかった。
ところがこの表は、スケジュールの方式に関係なく次の機能が「誰の行か」を決める
キーになっている。

- 自分のページ (`/me`)、BiS の取得済み、ロットの欲しい人行列と週制限の消化
- 軽減表の「自分のロール / 自分の担当」(L-8)
- 出席サマリー (W-19 / L-14 / L-20) と出席の自動突合のログ名 (W-6)
- 攻略リンクの既読の幹部表示

既定のモードは同期式なので、多くの固定ではこれらが**黙って空**になっていた
(出席サマリーはメンバー 0 件のとき空の結果を正常として返す)。画面の案内文
「設定のメンバー一覧に Discord ID を登録すると…」も、同期式では辿れなかった。

**実装**:

- 設定ダイアログはメンバーの一覧をどのモードでも読み、「Members」節を常に出す
  (節の id `native-members` はコマンドパレットのジャンプ先なのでそのまま)
- 説明文をモードで切り替える。自前作成式は従来どおり「スケジュール表の出欠列」、
  それ以外は「本人判定に使う表。スケジュール表の出欠列は外部シートのままで、
  ここで登録しても変わらない」。ローカルキーの注記 (本人として出欠を入力できない)
  は自前作成式だけに出す
- 同期式でこの表に行が入っても、同期式の画面・催促・スナップショットは表を読まない
  (催促の名前は外部シートから取る) ことを読み手の全件で確認した
- `docs/setup.md` (ja / en) の「7-3. メンバーを登録する」から「(自前作成式)」を外し、
  同期式でも登録するよう書き直した

**検証**: dev preview で、同期式に切り替えた状態の設定ダイアログに「Members」節が
出て、説明文が同期式のものになることを確認した (切り替えは DB に書かず、モードの
読み取りを一時的に固定して確認し、元に戻した)。

## 🩺 設定に「自動処理」を追加: Discord 取り込み・FFLogs 同期・催促などの最後の実行と成否、止まっていないかを見られるように (失敗に変わったら Discord に知らせることも可、既定 OFF)

**狙い**: 2026-10-01 の全体精査 (F-2)。自動処理 (cron) の成否は「レポート単位」でしか
残っておらず、ジョブ単位の「いつ走ったか / 通ったか」を持つ場所が無かった。失敗は
`console.warn` 止まりで、Vercel Hobby の runtime logs は 1 時間しか残らないので、
Discord の token 失効・FFLogs の cookie 失効・pg_cron の宛先違いは全部「静かに止まる」。

**実装**:

- `src/lib/cron-status.ts` (純関数): ジョブごとの最終実行 (`at` / 結果 / 理由 / 最後の
  成功 / 最後の失敗 / 連続失敗回数)。結果は 成功 / 一部 (時間切れで次回へ) / 何もせず
  終了 (OFF や時刻前) / 失敗 の 4 つ。日次は 26 時間、毎時は 2 時間 10 分を過ぎても
  走っていなければ「止まっている可能性」と出す (呼ばれなくなる故障は成否では分からない)
- `recordCronRun` (`src/lib/server/cron-status.ts`): cron の route 5 本が応答を返す直前に
  呼び、`app_settings` の `cron_status:<job>` に保存する。記録の失敗で cron 本体は失敗
  させない。失敗に**変わった**最初の 1 回だけ、設定で ON なら Discord 通知と同じ
  チャンネルに 1 行流す (既定 OFF、メンションなし、同じ失敗が続く間は再通知しない)
- 設定ダイアログに「自動処理」節 (admin のみ)。ジョブごとに予定 (毎日 01:00 など)・
  最終実行・結果と理由・連続失敗回数・最後の失敗・止まっている可能性を出し、
  失敗の通知の ON/OFF を置いた
- ⚠ `app_settings` はメンバー全員が読めるので、理由には秘密を入れない (route が返している
  英語のコードや失敗理由の要約だけ、300 文字まで)

**検証**: `scripts/check-cron-status.mjs` を足した (純関数の境界、cron の route
**すべて**が一覧に載り応答の直前で自分の名前で記録すること、記録の best-effort・
通知の条件、Action の admin 判定)。12 通りの書き換えで全部落ちることを確認した。
dev preview の設定ダイアログで、実際の Action 経由で 5 ジョブが「まだ記録がありません」
と出ること、Action の戻り値を一時的に差し替えて (DB には書かない) 成功・失敗 3 回連続・
一部・何もせず終了 + 止まっている可能性・未記録の各表示と見出しのバッジ (1 件失敗) を
確認した (差し替えは戻し済み)。実際の cron 実行での記録は、マージ後の次回実行で確かめる。
