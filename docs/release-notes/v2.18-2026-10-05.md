# v2.18 (2026-10-05)

## 📣 スケジュール: 自前作成式で複数のスケジュールがあるとき、開催確定の通知・出欠の催促・出席サマリーを全スケジュール分にした (通知と催促にはスケジュール名が入る。催促を 2 つの日で交互に送り直すことがあったのも止めた)

### 狙い

2026-10-01 全体精査の判断待ち F-9 (自前作成式の複数スケジュール「段階 2」) を、2026-10-02 のユーザー決定「やれるならやる」→「(b) で進めて」で入れた。段階 1 (#394、2026-09-18) は通知・催促・出席サマリーを **表示中のスケジュールだけ** にしていたので、零式と絶を同じメンバーで回す固定では、零式を表示中の間は絶の日の確定通知が飛ばなかった。

範囲は (b) 「通知・催促・出席サマリーを全スケジュール分にする」だけ。(a) 「メンバー・既定時刻・定期枠・自動確定をスケジュール別にする」はやらない — 段階 1 の前提 (スケジュールが違ってもメンバーはおおむね同じ) が変わっていない。同じ日付のメモが両方のスケジュールに出るのも既知の制約のまま。

### 実装

- 開催確定の通知 (`native-schedule-discord.ts`): 当日の確定日を全スケジュールから拾う。スケジュールが 2 つ以上あるときだけ文面に名前を入れる — 既定の書式は 1 行目が「【名前】本日の固定活動予定日です」、テンプレートには `{schedule}` / `{schedule_block}` を足した。自作テンプレートにどちらも無いときは先頭に `【名前】` が付く (どの予定の通知か分からなくなるのを防ぐ)
- 出欠の催促 (`attendance-reminder.ts`): 対象日の予定を全スケジュールから集め (同じ日に複数あり得る)、**その日の未送信の予定を 1 通にまとめて** 送る。予定ごとの本文は従来のテンプレートで作り、スケジュールが 2 つ以上なら名前を添える。Discord の上限 (2000 字) を超えたら末尾を切る
- 二重送信の印を「最後に送った 1 件」から「送った予定の組」(予定ごとの印を並べ替えて改行でつなぐ) に変えた (`pickReminderBatch`)。スケジュールが 1 つのときの予定の印は従来と同じ形なので、更新直後に同じ催促が二重に飛ばない。**ついでに止まる不具合**: 頻度が「毎日」などで 2 つの日に未入力があると、以前は毎時 cron で 2 つの催促を交互に送り直していた (印が 1 件しか覚えられないため)
- 出席サマリー (`attendance-summary-actions.ts`): 全スケジュールの開催日を母数にする (メンバーは全スケジュール共通)
- 設定: 複数スケジュールの説明文、通知のテンプレートの差し込みの説明、催促のプレビューを予定ごとの表示に

### 検証

- `check-attendance-reminder` に、予定の印 (1 つなら従来の形 / 2 つ以上は ID 付き)、印の組 (並べ替え・以前の 1 件の印も読める)、送る予定の選び方 (遠い日から / 次の実行で残りを送る / **交互に送り直さない** / 同じ日の 2 つのスケジュールはまとめる / 範囲外の印は落ちる / 手動送信)、本文のスケジュール名 (既定 / `{schedule}` / 自作テンプレートの先頭 / 名前なし / @everyone を崩す)、本文の上限 (サロゲートペアを割らない)、配線 (3 つの処理が表示中のスケジュールを読まない / 通知の差し込みと既定の書式)
- 変異 9 通り (印を今回分だけに戻す / 1 つでも ID を付ける / 同じ日の 2 つ目を落とす / 自作テンプレートに名前を付けない / 上限で文字を割る / 1 つでも名前を出す / 既定の書式に名前を入れない / サマリーで表示中を読む / 上限に収めない) がすべて検査で落ちる

## 📥 設定: 書き出したデータの取り込み (復元) を追加。同じ ID の行は上書き・無い行は追加・ファイルに無い行は消さない。書き込む前に表ごとの「追加 / 上書き」の件数を確認できる

### 狙い

2026-10-01 全体精査の F-3 の残り。#415 で種類ごとの JSON の書き出しを入れたが、書き戻す手段が無かった (「全データ初期化」の前に書き出しても、戻せなかった)。2026-10-05 のユーザー決定: **上書き (A)** (主キーが同じ行は上書き、無い行は足す、ファイルに無い行は消さない) + **確認画面あり**。

### 実装

- `src/lib/data-import.ts` (純関数): 書き出しのファイルの読み取り (別のアプリの JSON・版違い・知らない種類を弾く / 表は種類の並び = 参照される側が先 / 秘密になり得る設定キー・主キーが欠けた行を飛ばす / 種類に無い表は読まない)、主キーの取り出し、塊の分け方 (JSON のバイト数で 700KB 以下 — Server Action の受け取りの既定上限が 1MB)、取り込む順番の案内 (設定値 → コンテンツ → 予定 → ロット → 練習ログ → 明細)
- `src/lib/server/data-import-actions.ts`: 確認 (`countExistingImportRowsAction`、主キーだけを受け取り既存の数を返す。書き込まない) と取り込み (`applyImportBatchAction`、主キーで upsert)。どちらも admin を確かめてから service role (policy を張っていない表があるため)。秘密になり得る設定キーは書かない。delete は使わない
- 設定「データの書き出し・取り込み」に取り込みの欄: ファイルを選ぶ → 要約 (種類・書き出した日時・表ごとの行数・飛ばす行) → 「件数を確認 (書き込みません)」で表ごとの追加 / 上書き → 確認ダイアログ → 取り込み → 表ごとの結果 (失敗した塊と理由)

⚠ 日付メモは件数上限のトリガー (1 人 1 日付 10 件) が取り込みにも効くので、上限を超える日付の行は失敗として出る。秘密 (token / cookie) はファイルに無いので、取り込んだ後に設定し直す。

### 検証

- `scripts/check-data-import.mjs` (新規): 読み取り (別のアプリ / 配列 / 版違い / 知らない種類 / 種類の並びへの並べ直し / 主キーの欠け / 種類に無い表 / 書き出しの失敗 / 秘密の設定キー)、主キー (単一・複合・種類に無い表)、順番の案内、塊 (上限以下・順序・1 行で超える行)、**全種類の全表で主キーの列に schema の PRIMARY KEY / UNIQUE がある** (上書きが効く前提)、配線 (admin → service role / 入力検査 / 主キーで upsert / 秘密の設定キー / delete を使わない / 確認ダイアログの後 / 件数の確認が済むまで取り込めない)
- 変異 7 通り (一意でない列を主キーに / 読み取りで秘密のキーを飛ばさない / バイト数で分けない / 書き込みで秘密のキーを飛ばさない / 上書きせず足すだけ / 確認前に取り込める / 順番を入れ替える) がすべて検査で落ちる

## 🎬 練習ログ: YouTube の動画ごとに「チャプター」ボタンを追加。押すと pull ごとの区切り (例: 2:13 #1 1層 残42.0%) がコピーされ、動画の説明欄に貼るとチャプターになる

### 狙い

2026-10-01 全体精査の F-6 の C-2。練習の動画を YouTube に上げる人が、動画を見ながら pull ごとの区切りを手で打つ手間を消す。練習ログには pull の開始時刻と動画のオフセットが既にあるので、説明欄に貼るだけでチャプターになる文字を作れる。

### 実装

- `src/lib/video-chapters.ts` (新規・純関数): pull の名前 (`#回数 区間 結果`。回数は日の行の番号、区間は層 / フェーズ、結果は討伐なら CLEAR・それ以外は残%) と、チャプターの行の組み立て。動画の時刻は pull 行のリンクと同じ式 (`videoSecondsForPull`、秒は切り捨て) で出すのでリンクとずれない。録画開始より前の pull (`isBeforeVideoStart`) は入れない
- YouTube のチャプターの決まり (最初は `0:00` / 3 つ以上 / それぞれ 10 秒以上) に合わせる: 10 秒未満で次の pull が始まったものは前にまとめる、最初の pull が 10 秒より後なら `0:00` に「開始前」を置く (10 秒未満なら最初の pull を `0:00` にずらす)、3 つに満たなければ作らない (「作れません」と出す)
- 日の行 (`day-row.tsx`) の動画オフセットの欄で、YouTube の動画チップのすぐ右に「チャプター」ボタン (オフセットが動画ごとに違うため動画ごと。Twitch などには出さない)。押すとクリップボードにコピーして件数を出す

### 検証

- `scripts/check-video-chapters.mjs` (新規): pull の名前 (零式 / 下の層の討伐も CLEAR / 英語 / 絶のフェーズ / 残% が無い)、YouTube の決まり (開始前 / 時刻順 / 10 秒未満をまとめる / 0:00 にずらす / 映っていない pull を外す / 3 つ未満 / 秒の切り捨て / 1 時間超の表記 / 隣どうし 10 秒以上)、配線 (リンクと同じ式 / 日の行と同じ番号 / 画面と同じ pull #1 / その動画のオフセット / ボタンはチップのすぐ右で同じ名前 / YouTube だけ)
- 変異 13 通り (10 秒未満をまとめない / 並べ替えない / 映っていない pull も入れる / いつも開始前を置く / 0:00 にずらさない / 2 つでも作る / 四捨五入 / 討伐でも残% / 最終層だけ CLEAR / 英語でも「残」/ 説明の名前を番号だけに / YouTube 以外にも出す / 番号をレポート内で数え直す) がすべて検査で落ちる
- dev で合成データの一時ページ (コミットしていない) に日の行を描いて実測: URL の無い動画 1・YouTube の動画 2 (+1:35)・Twitch の動画 3・YouTube の「後半」(-25:00) → ボタンは動画 2 と「後半」のすぐ右だけ。動画 2 は 8 件 (`0:00 開始前` / `1:35 #1 1層 CLEAR` … 5 秒後に始まった #6 は #5 にまとめ)、「後半」は 4 件 (録画開始より前の #1〜#4 を外す)。クリップボードが拒否されたときはエラーの表示
