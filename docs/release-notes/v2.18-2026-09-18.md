# v2.18 (2026-09-18)

## 🗓 同期式のスケジュールを複数登録して切り替えられるように (登録すると元ページから名前を取得して一覧に表示)

**狙い**: 実機要望「登録式のスケジュールの切り替え機能が欲しい / 複数スケジュール
を切り替えられる機能、及び登録されたスケジュール名を取得して表示する」。同期式は
`app_settings.schedule_url` に URL を 1 本しか持てず、別のスケジュール
(例: 零式の固定と絶の固定) に切り替えるには URL を貼り替えるしかなかった。貼り替え
ると前の URL は消えるので、戻すには元 URL をどこかに控えておく必要があった。

**実装**:

- `app_settings.schedule_urls` (JSON 配列 `{id, url, name}`) に**登録リスト**を持つ。
  **表示中の URL は従来どおり `schedule_url`** に置いたままにした。ここが設計の要で、
  TOP 描画 (`getScheduleSourceUrl`)・cron 4 本・スナップショット・Discord 通知は
  全てこのキーを読むため、切り替えは「1 キーの差し替え」で全経路に効き、追加改修が
  要らない
- スケジュール名は元ページの `<h1 id="title">` から取得 (`extractScheduleName`)。
  取れないときは `<title>` を代替に使い、それも定型文なら null にして UI が URL の
  key を出す。鉛筆ボタンで手入力に上書きもできる
- ⚠ **character-sheets (デイコード) は存在しない key でも HTTP 200 を返す。**
  実測 (2026-09-18) では `<title>` が「データが存在しません。」、見出しが「画面を
  閉じてください。」のエラーページになる。status では判定できないので
  `isMissingSchedulePage()` で本文を見て、この場合だけ登録を止める。一時的な取得
  失敗 (タイムアウト / 5xx) では名前なしで登録を通す — URL は正しいのに元サイトが
  落ちているだけ、というときに登録できないのは不便なため
- 登録リストの保存 / 切替 / 名前取得はいずれも `assertAdminResult()` で admin gate。
  名前取得の fetch には同期式本体と同じ SSRF ガード (`isPublicHttpUrl`) を通す
- 設定ダイアログの「保存」ボタンは Discord チャンネル ID 専用になった (スケジュール
  の登録・切替は節の中で即時保存。名前の付け替え中に全員の表示が動かないよう、
  「登録の編集」と「今どれを見るか」は別の server action に分けてある)
- この機能より前から使っている固定は `schedule_urls` を持たないので、設定を開いた
  時点の表示だけ現 URL を先頭に補う (開いただけでは DB を書かない)

**検証** (dev preview + demo DB、実施後に DB は原状復帰):

- 存在しない key の URL を追加 → 「スケジュールが見つかりません (URL を確認して
  ください)」で登録を拒否
- 実在ページを追加 → 名前を取得して一覧に表示 (`Example Domain`)
- ラジオで切り替え → `app_settings.schedule_url` が切替先の URL に変わることを
  DB 側で確認
- 鉛筆で名前を手入力 → DB の `name` に反映
- 表示中の行は削除ボタンが無効。別の行に切り替えてから削除 → 確認ダイアログを経て
  一覧から消え、DB からも消える
- 名前の取り直しが失敗したときは既存の名前を保持したままエラートーストのみ
- 抽出 / 正規化の純関数は実ページ (エラーページ) と合成 HTML で 15 ケース実測
  (壊れた JSON・`javascript:` スキーム・重複 URL を落とすことを含む)
- 入力欄が `min-width:auto` で縮まずダイアログが横スクロールしていたのを実測で
  見つけて `min-w-0` を追加

## 🩹 設定: メンバー一覧の行が枠からはみ出し、名前の欄が潰れて読めなくなっていたのを修正

**狙い**: 上の機能を実機確認しているときに見つけた既存の崩れ。設定ダイアログの
**NATIVE SCHEDULE MEMBERS** を開くと、行の中身が枠に収まらず**ダイアログ全体に
横スクロールが出て**いた。さらに名前の列が幅 0 まで潰れ、**Discord ID も表示名も
見えない**状態だった。

**実装**:

- 実測 (2026-09-18): 行の子要素が 128 + 160 + 144 + 112 + 41 + 28 = 613px、
  対してダイアログ内側は 519px。`sm:flex-row` で横一列にするのに `flex-wrap` が
  無く、はみ出しがそのままスクロールになっていた (48 要素が最大 120px 超過)
- 行に `sm:flex-wrap` を付け、あふれる列は折り返して吸収する
- 名前の列は `sm:w-1/3` をやめ、`sm:min-w-[11rem] sm:flex-1` に。固定幅の兄弟に
  押し出されて 0 になるのを防ぎつつ、余りを受け取る
- ジョブの `<select>` は選択肢が長く (「暗黒騎士 (DRK)」)、内容幅が親の枠を 29px
  超えていたので `min-w-0 flex-1` で枠に収める

**検証** (dev preview):

- デスクトップ幅: ダイアログの `scrollWidth` 694 → **559 = `clientWidth`**、
  はみ出し要素 48 → **0**。名前の列は 0 → **180px**
- スマホ幅 (375px): はみ出し 0、ページ側の横スクロールも無し
- 修正は表示のみで、保存・削除・有効切替の挙動は変えていない
