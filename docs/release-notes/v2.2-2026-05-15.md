## 🐛 PR #132 — 上のコンテンツタブのカテゴリ切替は「現在のサブタブを引き継ぐ + 非表示タブのみ defaultTab にフォールバック」に再調整 (PR #128 挙動見直し)

**経緯**: [PR #128](https://github.com/yyamazaki-lym/raid-repository/pull/128) で「上の『コンテンツ』ドロップダウンからカテゴリを切替えた時に常に defaultTab に飛ぶ」挙動 (= カテゴリカードと同一) に統一していたが、ユーザー実利用で「攻略動画を見ている状態で他コンテンツに切替えた時に同じ動画タブに行きたい (見比べたい)」という要望が判明。一方で Phase 17 ([PR #123](https://github.com/yyamazaki-lym/raid-repository/pull/123)) で導入された `tab_config.{tab}.enabled=false` でタブを非表示にしているカテゴリでは、引き継ごうとしているサブタブが存在しない (= 空ページに着地する) ケースが出るため、その場合のみ defaultTab にフォールバックする必要がある。

**変更内容** [category-switcher.tsx](src/components/portal/category-switcher.tsx):

- `pathname` から `/category/{slug}/{sub}` 形式で現在のサブタブ id を抽出し、`isCategoryTabId` ([src/lib/supabase/types.ts:168](src/lib/supabase/types.ts)) で `CategoryTabId` (mitigation / loot / strategy / videos / macros) のいずれかに narrowing。非カテゴリページから開いた / 子セグメントが規定タブ id でない場合は `null` で次段にスキップ
- 各カテゴリ項目の `defaultHref` を「`candidateTab !== null && cat.tabConfig?.[candidateTab]?.enabled !== false` ならその id、それ以外なら `cat.defaultTab`」に置換。判定式は [sub-tabs.tsx:136-137](src/components/portal/sub-tabs.tsx) の描画判定 (`cfg?.enabled === false` で非表示) と完全一致させ「SubTabs から消えているタブには上のコンテンツタブからも飛ばない」を保証
- import を `import { isCategoryTabId, type Category } from '@/lib/supabase/types'` に変更し、既存 type guard を再利用

**変更しない範囲**: 同ファイル内 5 個のサブページショートカットアイコン (盾 / サイコロ / 本 / フィルム / 端末) は意図的に特定タブを指す UI なので従来通り該当タブに直接遷移。カテゴリカード ([category-list.tsx:391](src/app/(portal)/category/category-list.tsx)) と `/category/{slug}` root redirect ([page.tsx](src/app/(portal)/category/[slug]/page.tsx)) は「カテゴリ一覧 / URL 直叩き」起点であり「現在のサブタブ」概念が無いため defaultTab 直行のままで OK (今回の対象外)。

**検証**: ユーザー実機で (A) videos 画面で別カテゴリ選択 → 相手 videos に着地 / (B) videos 画面で `tab_config.videos.enabled=false` のカテゴリ選択 → defaultTab に着地 / (C) 非カテゴリページ (/) からカテゴリ選択 → defaultTab に着地 / (D) サブページアイコンは従来通り該当タブ直行 / (E) カテゴリカードと URL 直叩きは defaultTab 直行のまま、を確認。

## 🐛 PR #130 — Discord 添付画像 URL を Storage に自動退避して 24h 失効を回避

**経緯**: 攻略タブの「画像追加」ダイアログで Discord 添付画像の CDN URL (`https://cdn.discordapp.com/attachments/...?ex=...&hm=...`) を貼り付けて kind='image' で保存すると、24 時間後に Discord 側で署名が失効して画像が 403 を返し、一覧で「画像URL不正」表示に化ける症状がユーザーから報告された。Discord は 2023 年末以降、CDN 添付 URL に `ex=` (expiry) / `is=` / `hm=` (HMAC) の署名クエリを付けて配信しており、CDN URL を DB にそのまま保存すると恒久参照できない。

**真因**: [createCategoryLinkAction](src/lib/server/categories-actions.ts:1308) は kind='image' のとき入力 URL をそのまま `category_links.url` と `thumbnail_url` に格納し ([L1381-1383](src/lib/server/categories-actions.ts:1381) で `thumbnailUrl = input.url`)、Storage への退避を行っていなかった。ローカルファイル経路 ([image-form-dialog.tsx:104-150](src/components/portal/image-form-dialog.tsx:104)) は `category-strategy-images` バケットにアップロードするため永続するが、URL 直貼り経路には同等の退避ロジックが存在しなかった。

**変更内容**:
- **新規** [src/lib/server/discord-image-migrate.ts](src/lib/server/discord-image-migrate.ts): `isDiscordCdnUrl(url)` で `cdn.discordapp.com` / `media.discordapp.net` ホスト判定、`migrateDiscordImageToStorage(url, categoryId)` で 15s タイムアウト + Content-Type ホワイトリスト (png/jpeg/webp/gif) + 5MB 上限 + service role 経由 Storage upload を行い、公開 URL を返す helper。例外は throw せず `{ ok, reason }` で返し、呼び出し側がそのままダイアログにエラー文言として返せる設計
- **編集** [src/lib/server/categories-actions.ts](src/lib/server/categories-actions.ts): `createCategoryLinkAction` で `input.kind === 'image' && isDiscordCdnUrl(input.url)` のとき INSERT 直前に migrate を実行、成功時に `url` / `thumbnail_url` を Storage 公開 URL に差し替え。`updateCategoryLinkAction` も `patch.url` が Discord CDN URL のとき既存行の `kind` を SELECT し、image だったら同じ migrate を通す (`url` と `thumbnail_url` を一緒に更新)
- **編集** [src/components/portal/image-form-dialog.tsx:302-306](src/components/portal/image-form-dialog.tsx:302): ヘルプ文言に「Discord 添付 URL は 24h で失効するため自動的に Storage に取り込みます」を追記

**スコープ**: cdn.discordapp.com / media.discordapp.net のみ。imgur など他の外部画像 URL は従来どおり素通し (将来別ホストでも失効が発生したら同 helper を流用して拡張可能)。strategy kind の og:image 経路は Discord channel HTML が og:image を返さないため事実上発生しないとして今回スコープ外。既存 DB に残っている期限切れ行は今回触らない (新規追加 / 編集のみ守る)。

**検証**: dev preview で admin として「画像追加」を開き、生きた Discord CDN URL を貼って追加 → Supabase Studio で該当 `category_links` 行の `url` / `thumbnail_url` が `*.supabase.co/storage/v1/object/public/category-strategy-images/...` になっていることを確認。期限切れの古い CDN URL では「Discord 画像取得失敗 (HTTP 403) — URL 期限切れの可能性」がダイアログに表示される。imgur 等の他外部 URL は migrate されず元 URL のまま保存される回帰確認も実施。

## ✨ PR #128 — 上の「コンテンツ」タブからのカテゴリ切替もカテゴリごとの既定タブ (defaultTab) に着地させる

**経緯**: Phase 17 ([PR #123](https://github.com/yyamazaki-lym/raid-repository/pull/123)) でカテゴリごとの既定タブ (`Category.defaultTab`) を導入し、(a) カテゴリ一覧のカテゴリカード click と (b) `/category/{slug}` (タブ未指定 URL) アクセス時の redirect の 2 箇所では既定タブに飛ぶようになっていた。しかしヘッダー上の「コンテンツ」ドロップダウンメニュー内からカテゴリを選んだときだけ、現在のサブタブ (`subSegment`) を引き継ぐ古い挙動が残っており「カテゴリカードと挙動が一致しない」とユーザーから報告。

**変更内容** [category-switcher.tsx](src/components/portal/category-switcher.tsx): ドロップダウン内カテゴリ項目の `defaultHref` を、現在の subSegment ベース (`/category/{slug}/{subSegment}`) から `cat.defaultTab` ベース (`/category/{slug}/{defaultTab}`) に置換し、未使用になった subSegment 計算 (pathname の正規表現マッチで「/category/{slug}/{sub}」を抽出するロジック) ごと削除。これでカテゴリカード / root redirect / コンテンツドロップダウンの 3 経路すべてが「常に defaultTab に着地」で統一。

**変更しない範囲**: 同ファイル内の 5 個のサブページショートカットアイコン (盾=軽減 / サイコロ=ロット / 本=攻略 / フィルム=動画 / 端末=マクロ) は意図的に特定タブを指す UI なので従来通り該当タブに直接遷移する挙動を維持。`tab_config.enabled=false` のフォールバックは既存 2 箇所も実装していないため、3 箇所まとめて将来対応する想定でここでは入れない。

**検証**: ユーザー実機で (a) 非カテゴリページから「コンテンツ」を開いて任意カテゴリ選択 → defaultTab に着地、(b) カテゴリ A のロット画面から B を選択 → B の defaultTab に着地 (ロットを引き継がない)、(c) defaultTab を変更すると上タブからの遷移にも即反映、(d) サブページアイコンは従来通り該当タブへ直行、を確認。
