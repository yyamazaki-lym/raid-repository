# ログ担当の手引き

最終更新: 2026-09-07 (W-34)

練習ログ (FFLogs 連携) を回す担当のための手引き。**属人化を下げる**のが目的で、
担当が抜けても次の人がこの 1 枚で引き継げる状態を目指す。

## この portal が FFLogs をどう使っているか

portal は **ブラウザだけで動く**設計で、ゲームクライアント側のプラグイン
(Dalamud / ACT 連携) は一切扱わない。したがって

- **ログの計測そのものは FFLogs の Uploader (ACT 系) が行う** — portal の外
- portal は **アップロード済みのレポートを読むだけ**

という分担になる。「portal を入れたからログが取れる」わけではないので、
**誰か 1 人が計測して上げる**運用が必要。

## 誰が計測するか

- **1 人でよい。** FFLogs のレポートは PT 全員分の情報を含むので、8 人が
  それぞれ上げる必要はない (むしろ重複レポートが増えて portal の取り込みが
  分散する)。
- **固定で担当を決めておく。** 「今日は誰が上げた?」を毎回確認するのが
  一番の事故源。回線が安定している人 / 遅刻が少ない人が向く。
- **サブ担当を 1 人決める。** 主担当が休んだ日にログが残らないのを防ぐ。

## portal がレポートを見つける経路 (2026-09-07 追加)

portal は既定では **貼られた URL からしかレポートを知らない** (動画の
FFLogs URL、日付メモの URL、活動日に紐づけた URL)。設定 → 練習ログの通知の
「レポートの発見元」で、貼らなくても見つける経路を選べる。

| 発見元 | 何を見るか | 向いている固定 |
|---|---|---|
| **貼られた URL のみ** (既定) | 従来どおり | URL を貼る運用が回っている固定 |
| **guild から自動** | FFLogs 上の static (guild) のレポート一覧 | Uploader で guild を選んで上げている固定。guild ID の入力が必要 |
| **自分のアカウントから自動** | 接続した FFLogs アカウントのレポート一覧 | guild を作っていない固定 (計測担当が個人アカウントで上げている) |

**既定を自動発見にしていない理由**: guild で討滅やレイド以外も回している
固定では、無関係なレポートが取り込み候補に大量に入る。1 回の取り込み枠
(40 件) を食い、未分類レポートの一覧も伸びて診断が読みにくくなる。だから
**選んだときだけ**動く。

**「自分のアカウントから自動」は Public のレポートしか拾えない。** FFLogs の
API 仕様で、本人の OAuth でも Unlisted / Private は一覧に出てこない
(実測で確定)。下の「Unlisted 推奨」と噛み合わないので、Unlisted 運用の固定は
**guild か、従来の URL 貼り付け**を使う。guild 経由で Unlisted が取れるかは
本番の guild で確かめてほしい (API の挙動が公開されていない)。

自動発見で見つけたレポートも、取り込み後の振り分け (どのコンテンツか) は
zone / encounter から従来どおり行われる。誤って別コンテンツに入ったときは
練習ログの「再分類」、取り込みたくないレポートは「ログ削除」で除外できる
(除外したレポートは自動発見でも復活しない)。

## 公開範囲は unlisted を推奨

FFLogs のレポートは Public / Unlisted / Private を選べる。**Unlisted 推奨**。

| 設定 | portal から読めるか | 外部から見えるか |
|---|---|---|
| Public | ○ | 誰でも見える (ランキングにも載る) |
| **Unlisted** | ○ | URL を知っている人だけ |
| Private | △ (認証が必要・失敗しやすい) | 本人と guild のみ |

- Public だと個人のパフォーマンスが検索から辿れる。固定内の練習ログを
  外に晒す必要はない。
- Private は portal 側の取り込みが**認証に依存して失敗しやすい**
  (取り込めなかったレポートは練習ログの「取り込めていない」欄に出る)。
- Unlisted なら「URL を知っている人だけ」= 実質固定内限定で、portal からは
  普通に読める。**迷ったら Unlisted。**

## Auto Logging (回し忘れ対策)

FFLogs は 2026 年に **Auto Logging** を追加した
([発表](https://www.patreon.com/warcraftlogs/posts/feature-auto-163794583))。
対象コンテンツのルールを設定しておくと live log を自動で開始してくれる機能で、
「Start ボタンを押し忘れて 1 時間分が残っていない」という一番多い事故に
効く。

- 課金条件は 2026-09 時点で未確認。使えるなら設定しておく価値が高い。
- 自動開始でも**アップロード担当が起動していること**が前提なのは変わらない。

## パッチ週の注意

パッチ当日〜数日は次のことが起きる。**この週だけは「ログが変」を疑う前に
以下を確認する。**

1. **Uploader の更新待ち。** ゲーム側の更新に Uploader が追いつくまで
   計測できない / 壊れた値になることがある。
2. **zone / encounter ID が変わる。** FFLogs 側でコンテンツの ID が
   振り直されると、portal のコンテンツ判定 (名前と zone/encounter の対応)
   が追いつかず「どのコンテンツにも割り当てられない」レポートになる。
   → 練習ログの **「レポートを診断」** で zone 名と encounter ID を確認し、
   必要ならコンテンツ編集で「進行モデル」を明示するか、判定辞書の追加を
   依頼する。
3. **旧コンテンツが Legacy zone に畳まれる。** 拡張をまたぐと絶が
   `Ultimates (Legacy)` にまとめられ、fight 名がボス名 (「Omega」など) に
   変わる。portal 側は対応済みだが、新しいパターンが出たら診断結果を
   添えて報告する。

## 取り込みが動かないときの順番

1. 練習ログの **「同期」** を押して、結果のトーストを読む
   (「残り N レポート」「v2 N 件・代替 M 件」が出る)。
2. **「取り込めていない」欄**を見る。理由が出ている。
   - `private` → レポートを Unlisted にしてもらう
   - `unassigned` → コンテンツに割り当てられていない → 「レポートを診断」
3. **「レポートを診断」** で zone / タイトル / encounter / 難易度を確認。
   分類が違っていれば **「いまの分類器で再分類」** を押す。
4. それでも解決しなければ、診断結果のテキストをそのまま共有して報告する
   (zone 名と encounter ID が分かれば大半は辞書の追加で直る)。

## 動画とログを紐づける

pull ごとに「動画のこの瞬間」へ飛べるようにするには、レポートごとに
**動画とオフセット**を登録する。

1. 攻略/動画タブに動画を登録し、その動画の Logs URL に FFLogs のレポート
   URL を入れる (同期が動画 → レポートの対応を自動で拾う)。
2. 練習ログで日を開き、**動画オフセット**のチップを押す。
3. **オフセット = 動画の中で「その日の 1 本目の pull の戦闘が始まる」秒数。**
   例: 動画の 0:56 で 1 本目が始まるなら `56`。
4. 同じ日に複数の動画 (前半 / 後半・視点違い) を上げた場合は
   **「動画を追加」** で 2 本目以降を登録する。**オフセットは動画ごとに
   別**なので、投稿ごとに入れる。

## やらないこと

- **ゲームクライアント側の自動化** (Dalamud プラグイン連携・ACT のマクロ
  操作)。portal はブラウザだけで完結させる方針。
- **個人 DPS の集計・ランキング。** portal は PT としての到達度しか扱わない
  (PT 合計 DPS と死亡数は PT 単位の値で、個人の内訳は DB にも持たない)。
