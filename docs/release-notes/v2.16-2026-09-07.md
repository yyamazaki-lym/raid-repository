## 🐛 練習ログ: 拡張をまたいだ絶 (Ultimates (Legacy)) のレポートが取り込めなかったのを修正 — pull の encounter 名で振り分け

**実機報告**: 絶オメガ検証戦の練習ログが 2024-06-18 で止まり、FFLogs 側にある 2024-07 以降のレポート (Dawntrail 期) が取り込まれない。「分類が拡張ごとに違っているのでは」という指摘どおりでした。

**原因**: FFLogs の zone は拡張ごとに切り直され、旧拡張の絶は現行拡張では **"Ultimates (Legacy)" という 1 つの zone** にまとめられます (絶バハ / 絶アルテマ / 絶アレキ / 絶竜詩 / 絶オメガがすべて同じ zone)。レポートのタイトルも「絶シリーズ（過去）」のように何の絶か書かれません。portal のカテゴリ判定は **レポート単位** の zone 名 / タイトルしか見ていなかったため、こうしたレポートは「カテゴリ未確定」のまま、どの練習ログにも出ませんでした。

**修正**: fight (pull) には encounter 名 ("The Omega Protocol" / "Dragonsong's Reprise" など) が付くので、**fight ごとに** encounter 名をコンテンツ分類器に通してカテゴリを決めるようにしました (`src/lib/fflogs-category.ts` に純関数として切り出し)。優先順位は「fight 名で一意に決まるカテゴリ → レポート単位の解決 (zone ID / zone 名 / タイトル) → 動画リンク由来」。同じ夜に 2 種類の絶をやったレポートも、それぞれのカテゴリへ振り分けられます。レポート台帳の代表カテゴリは fight の最多で決めます。零式の fight 名はボス名なので分類器に当たらず、従来どおりレポート単位の判定です。

- **既に取得済みで未確定のレポート**: 次の同期の「オフライン再解決」で、保存済みの fight 名から fight ごとに再分類します (FFLogs は叩きません)。絶オメガの 2024-07 以降がこれで出るはずです。
- 取り込み難易度の下限 (`fflogs_min_difficulty`) も fight ごとのカテゴリで判定します。
- `expected_fflogs_zone_ids` に Legacy zone を複数の絶カテゴリへ設定していても (= レポート単位では曖昧) fight 単位で決まります。

**検証**: `scripts/check-fflogs-category.mjs` (新規、13 ケース: Legacy zone + 汎用タイトルは決められない / fight 名で決まる / 零式ボス名は決まらない / 代表カテゴリ) と `tsc` / `eslint` / `check-changelog`。実機では **次回同期後に絶オメガの 2024-07〜2025-01 のセッションが並ぶこと** を確認してください。出ない場合、そのレポートが portal に未登録 (動画にも日程ログにも URL が無い) の可能性があるので「URL から取り込む」に貼ってください。

## 🔁 練習ログ: 同期結果に「残り N レポート」を表示 / フェーズ滞在時間の母数 (情報のある pull 数) を明示

**実機報告**: 絶竜詩のフェーズ滞在時間が「登録ログ全 123 pull」で、1047 pull あるのに P7 が 12 分しかない。

**背景**: フェーズ遷移と死亡イベントは 2026-09-06 (2.15) 以降に取得した pull にしか入っていません。それより前に同期したレポートは「1 回の同期で最大 40 レポート」ずつ取り直す設計 (FFLogs のポイント消費と 120 秒の時間予算のため) なので、レポート数が多い固定では数回〜十数回の同期が要ります。ところが画面には「※途中まで」としか出ず、あと何回押せばいいのか分かりませんでした。

**変更**:
- 同期の結果に、今回の枠に入らず次回に持ち越したレポート数 (`remaining`) を含め、トーストに「※残り N レポートは次回 — もう一度「ログを同期」を押すと続きを取得します」と出します。0 になれば取り直し完了です (cron でも毎日 40 件ずつ進みます)。
- フェーズ滞在時間カードの括弧書きを、母数が全 pull より少ない間は「フェーズ情報のある N / 全 M pull — 残りは同期で取り直し中」に。全件そろえば従来の「登録ログ全 N pull」。

**検証**: `tsc` / `eslint` / `check-changelog`。

## 🚦 同期: 旧レポートの取り直しを private 再試行より先に処理 / 取得経路 (v2 ・ 代替) の内訳を表示

**実機報告**: 「ログを同期」を押しても、フェーズ情報のある pull が 123 のまま増えない。

**原因の候補は 2 つ**で、どちらも画面から見えなかったので両方に手当てしました。

1. **枠の取り合い**: 手動同期は恒久失敗 (private) のレポートも毎回再試行します。private が多い固定では、この再試行 (ほぼ同じ結果になる) が 1 回 40 件の枠を先に埋め、旧レポートの取り直しに順番が回りませんでした。取得順に優先度を付け、通常 (未同期 / 直近 / URL 指定) → 旧レポートの取り直し → private 再試行、の順で処理します。同じ優先度の中は従来どおり新しい日付から。
2. **取得経路**: フェーズ遷移と死亡イベントは **FFLogs v2 (OAuth) で読めたレポートだけ** に入ります。unlisted / private で v2 が拒否され、v1 API や cookie の代替経路で取れたレポートは fights の骨格 (pull 数・到達度・残 HP%) だけで、取り直しても埋まりません。同期結果のトーストに「経路: v2 N 件・代替 M 件 (代替経路はフェーズ・死亡情報なし)」を出し、フェーズ滞在時間カードの括弧書きにも hover でこの説明を付けました。代替経路になっているレポートを埋めたい場合は、アップロードした本人の FFLogs 連携 (OAuth) か、レポートを Public にする必要があります。

**検証**: `tsc` / `eslint` / `check-changelog`。

## 🩺 練習ログ: URL 取り込みは貼ったコンテンツのログとして取り込む / レポート診断と「このコンテンツに割り当て」を追加

**実機報告**: Ultimates (Legacy) の絶オメガ 9 本を URL 取り込みしても、絶オメガの練習ログに出ない。

DB を見られない側からは「取得できていないのか、取得できたが未分類なのか、別コンテンツに付いたのか」を絞れなかったので、3 つを入れました。
