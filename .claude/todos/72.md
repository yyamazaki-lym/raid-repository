## 症状の切り分け (重要)

| 操作 | 結果 |
|---|---|
| click open → outside click close | ✅ 残留なし |
| 一度 click 経路を通した後の hover → mouseleave | ✅ 残留なし |
| **リロード直後の first hover → mouseleave** | ❌ **白枠が出続ける** |

= リロード直後の **hover-only 経路の初回 close** だけで残留する。click を一度でも通すと以後 hover でも OK。

## 真因仮説 (未確定)

1. **React 19 hydration race**: hydration 完了直後の最初の portal mount が不完全な状態で hover trigger される。`PopoverPrimitive.Portal` の内部 useEffect が初回だけ subtle な順序問題を起こす
2. **hover trigger 経路の初期化スキップ**: `mouseenter` → `setOpen(true)` で Base UI Popover が click 経路と異なる初期化を踏む。click では focus 移動 + pointer events の event.type/target が異なるが、hover では一部スキップされる internal cleanup がある
3. **portal lift race**: portal node が `<PopoverPrimitive.Portal>` で body 直下に持ち上がるタイミングで、初回だけ unmount path の cleanup ref (Base UI が node の親 ref を握る) が貼られない

## 調査方針

### Phase 1: 再現環境構築

- `next build && next start` で worktree 内に **production build を local 起動** (dev preview では production-only race を再現できない)
- Claude Preview もしくは Claude in Chrome で hover を実際に発火 (matchMedia `(hover: hover)` が true を返す環境必須)
- DOM mutation を MutationObserver でログして残留 node の attributes / children / shadow root を完全観察

### Phase 2: Base UI 内部の確認

- `node_modules/@base-ui/react/popover/` のソースを Explore agent で読み、open/close の internal cleanup 経路で hover-trigger 特殊化 / focus 依存パスがあるか確認
- 特に `useEnhancedClickHandler` や `useFocusableWhenDisabled` 系で hover open path が click open path と異なる初期化を踏む箇所
- React 19 の `use()` / `useTransition` 等で portal cleanup が deferred になる経路がないか

### Phase 3: 修正案の候補

#### 案 A: hover open 前に「click 経路を裏で 1 度通す」hack

```ts
const [bootstrapped, setBootstrapped] = useState(false);
const onMouseEnter = () => {
  if (!bootstrapped) {
    triggerRef.current?.click();  // close 即発火
    setBootstrapped(true);
    requestAnimationFrame(() => setOpen(true));
  } else {
    setOpen(true);
  }
};
```

リスク: 初回 mouseenter で popover が一瞬開閉する flash が見える可能性。

#### 案 B: 常駐 MutationObserver ガード

`schedule-list.tsx` (CommentPopover の親) もしくは layout で起動:

```ts
useEffect(() => {
  const observer = new MutationObserver(() => {
    document.querySelectorAll('[data-slot="popover-content"]:not([data-open])').forEach(n => n.remove());
  });
  observer.observe(document.body, { childList: true, subtree: true });
  return () => observer.disconnect();
}, []);
```

リスク: 全 popover に影響、open 直前の transient state を誤射する race あり。throttle 必須。

#### 案 C: hover open を諦めて click open に固定

`CommentPopover` の hover handler を完全削除、Base UI の click trigger に統一。touch device は元々 click。
リスク: UX 後退 (現状 hover で popover を素早く読めるのが利点)。

#### 案 D: hover open を維持しつつ、setOpen(true) の前に triggerRef.current?.focus() を強制

click 経路では trigger に focus が移動するので、hover でも同じ side effect を踏ませる:

```ts
const onMouseEnter = () => {
  triggerRef.current?.focus({ preventScroll: true });
  setOpen(true);
};
```

リスク: focus ring が見える、accessibility 上で hover で focus が動くのは違和感。

### Phase 4: 推奨優先順位

D → A → B → C の順で試す。D が最低コスト + 副作用最小、もし駄目なら A、それでも駄目なら B、最後の手段が C。

### 真因 (case (a) data-open="" 残置 確定)

- `keepMounted` 配下でも、**複数 Popover の同時 `setOpen(false)` 並行発火** で `data-open` 属性が外れない race が発生
- Base UI 内部の close path (useTransitionStatus 等) が batch race で skip される
- 案 T (`keepMounted`) と 案 E (`[&:not([data-open])]:hidden`) は「`data-open` が外れる」ことを前提にしていたため両方失効
- 「ページ内 click で消える」= Base UI `useDismiss` の `pointerdown` listener が発火して個別 Popover を確実に close path に乗せる
- ユーザー報告の「リロード直後 first hover → leave で白枠」は、本番では複数メンバーアイコンを順次素早く hover していく自然な行為で発火していた

### 次案: 案 J (controlled unmount)

Plan の case (a) 推奨対策。`<PopoverContent>` を `{open && <PopoverContent />}` で React レベルの条件付き render に変更し、open=false 遷移時に確実に DOM tree から外す (`data-open` 属性に依存しない unmount path)。

実装方針:
- `keepMounted` は撤去 (案 T 否定)
- `[&:not([data-open])]:hidden` も撤去 (案 E 否定、案 J で不要化)
- 案 A bootstrap click は維持 (副作用なし、予防策)
- 入場アニメ (`data-open:animate-in / fade-in-0 / zoom-in-95`) は維持
