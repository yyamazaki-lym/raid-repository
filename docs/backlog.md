### L-18. 自分のメモが編集できない / 匿名メモを消したい — 2026-09-09 実装

**報告**: 「自分のメモも編集できない。匿名の場合は消せるようにしたい」。

**原因** (実コードで確認): TODO #92 (所有者ベース化) で `viewerId` の配線が
2 箇所抜けていた。

- `(portal)/page.tsx` の **sync 分岐が `currentDiscordId` を渡していない**
  (native 分岐だけ渡していた)。既定モードは sync なので **本番では viewerId
  が常に null** = admin 以外は誰も自分のメモを編集できない
- `schedule-past-simple.tsx` が `viewerId` / `viewerIsAdmin` を**一切渡して
  いない**。過去チップの popover は **admin でもボタンが出ない**

加えて `author_user_id` は 2026-09-09 に足した列なので、**それ以前のメモは
全部 NULL** (所有者不明) で、自分が書いた古いメモも触れない。

**やったこと**: 上記 2 箇所を配線。**所有者不明の行は「削除だけ」ログイン済み
メンバー全員に開ける** (ユーザー決定)。⚠ UPDATE は開けない — 誰の物か
分からない行の文面を別人が書き換えられると履歴が黙ってすり替わる。判定は
`src/lib/memo-permissions.ts` に集約し、RLS (schema 7a-2) と同じ規則を
`scripts/check-memo-permissions.mjs` で突き合わせる。demo のゲストは
`viewerId` を null に正規化 (anon は RLS で必ず弾かれるため)。

⚠ **引き換えのリスク**: 非 admin 1 人が PostgREST 直叩きで**所有者不明のメモ
を一括削除できる**余地が戻る (7a-2 で塞いだ穴のうち旧行に限った再開放)。
所有者つきの行 (2026-09-09 以降) は他人には消せない。

⚠ **未実測**: RLS の実行検証はローカルに Postgres が無いためできていない
(構文は libpg_query で検証済み)。schema は main push で自動反映されるので、
**反映後に「非 admin で所有者不明のメモが実際に消せるか」を 1 回確認する**。

### L-19. 画像が読み込めないときの代替表示 — 2026-09-09 実装

**報告**: 「コンテンツ背景と攻略画像は表示される。画像がない、読み込めない
場合、代替画像などにしたい」。

**原因**: URL の**形式**が壊れている場合は `safeHref` / `isSafeUrl` が弾いて
「画像URL不正」が出るが、**形式は正しいのに実体が取れない** (Storage から
削除 / imgur 側で削除 / 直リンク禁止で 403 / Google フォトの共有期限切れ)
受けが無く、壊れた img が出るだけだった。背景は alt が空なので**何も出ない**。

**やったこと**: `components/portal/image-with-fallback.tsx` を追加し、
`onError` でアイコン + 「画像を読み込めませんでした」に差し替える。適用先は
コンテンツカードの背景 (文言なし・薄いアイコンのみ — カード名と重なるため) /
攻略の画像カード / アルバムのカード / 拡大表示。失敗した URL 自体を state に
持つので、画像を直せば自動で復帰する。

### L-7. 死亡原因を表示言語で出す — 2026-09-08 実装

**報告**: 練習ログの「ワイプ原因」と pull 行の致命技が英語のまま
(`DRK ← Xtreme Wave`)。表示言語に合わせて出したい。

**原因** (実コードで確認):

- 日本語化の仕組みは 2026-09-06 に入っている
  (`lib/xivapi-actions.ts` + `server/xivapi-action-names.ts`) が、**同期の
  後段でしか走らない**。`death_events` の `ja` は同期時に書かれるので、
  **それ以前に取り込んだ pull には `ja` が無く、英語名のまま残る**。
  再同期は 1 回に 1 レポートしか取り直さないので自然には埋まらない。
- 表示は `deathAbilityLabel()` が `ja ?? ability` を返すだけで
  **locale を見ていない**。英語表示に切り替えても日本語名が出る
  (逆向きの取り違え)。
- W-10 の軽減表の雛形 (`logs/boss-damage-timeline.ts`) も同じで、ボスの
  技名が英語のまま。こちらは押したときに取りに行くので保存の問題は無い。

**やったこと**:

- `deathAbilityLabel(d, locale)` / `wipeAbilityLabel(w, locale)` で
  **表示言語の名前だけを使う** (無ければ FFLogs が返した名前に落ちる)。
  別言語の名前で埋めることはしない。同期時は ja / en を**両方**保存する。
- 保存済みの pull は **描画時に足りないぶんだけ引く**
  (`server/wipe-ability-names.ts`)。表示に要るのは「最初の死亡の技名」だけで
  action ID の種類は数十なので、上限 100 ID / 締切 2.5 秒 / プロセス内 7 日
  キャッシュで足りる。⚠ **一括 UPDATE は選ばなかった** — pull は 20,000 行
  規模で UPDATE の本数が読めず、admin がボタンを押すまで直らない。
- `WipeSummary` に `id` / `ja` / `en` を持たせ、`ability` は**生の名前**に
  戻した (server 側の `summarizeWipe` は locale を知らないため、言語の選択は
  表示直前に寄せた)。
- pull 詳細 (UI-14) と W-10 のボス技名も表示言語で引く。

**実測**: XIVAPI の実応答で ja (`邪竜爪牙`) と en (`Hatebound`) が別の欄に
入り、`formatWipeLabel` が表示言語で選ぶことを確認 (検査スクリプトは
`check-xivapi-actions` / `check-fflogs-fight-detail` を新契約へ更新)。

### L-8. ロール設定が分かりにくい / 軽減表のどの列が自分か分からない — 2026-09-08 実装

**報告**: ロールの設定場所が非常に分かりにくい。軽減表もどの列が対応する
ロール名なのか分からない。

**原因** (実コードで確認):

- ロール (`native_schedule_members.role`) の編集 UI は
  **設定 → メンバー一覧の中だけ**で、しかも `canEdit`(= admin) が無いと
  触れない。**本人が自分のロールを設定する経路が無い**。
- 軽減表の絞り込みが見ているのは **localStorage の「表示名」** で、
  これを `findMemberColumn()` が**シートの見出し行**と突き合わせる。
  ロールも `roleOfName(memberRoles, 表示名)` で引くので、**表示名が
  メンバー一覧の表示名とシートの見出しの両方に一致していないと
  どちらの絞り込みも効かない**。
- 実機の軽減表は見出しがジョブのアイコン画像で、担当は**チェック列の
  ラベルに「アドル (赤魔道士)」の形でジョブ名として入っている**。
  報告者は表示名に「赤魔道士」と入れていて、これは意味としては正しいが
  見出し行には無いので「一致する列が見つかりません」になる。
- 列のロール色は `sheet-cards.tsx` の `roleOf()` が **MT/ST/H1/D1 の略号**
  だけを見るので、ジョブ名のラベルでは色も付かない。

**やったこと**:

- `lib/jobs.ts` (22 ジョブ / 日本語名 / 略称 / ロール)。⚠ キーは既存の
  `JOB_ABBR` と **1 対 1** で、対応が崩れると `check-jobs.mjs` が落ちる
  (新しいゲームデータ表を増やしたのではなく、既にある表に列を足した形)。
- `native_schedule_members.job` を追加。**ロールはジョブから導出**し、
  未設定なら従来の `role` に落ちる。⚠ CHECK でジョブ名を列挙しない —
  拡張でジョブが増えるたびに migration が必要になるのを避け、妥当性は
  アプリ側 (`isJobKey`) で見る。
- **本人が保存できる** `setMyJobAction` (自分の行だけを更新。service role
  だが絞り込み条件は固定)。UI は**使う場所**に置いた: 軽減表タブの
  絞り込みの隣と `/me`。幹部が代わりに埋める経路は設定のメンバー一覧に残す。
- 軽減表の絞り込みを**ジョブで当てる** (`buildColumnJobs` が列ラベルの
  括弧からジョブを読む)。表示名で見出しに当てる従来の判定も残す
  (見出しにメンバー名を書く固定を壊さない)。
- チェックのチップを**ロール色**で塗り、凡例を表の上に出す。絞り込み
  ボタンにも実ロール名 (「自分のロール (DPS)」) を出す。
- ⚠ 1 文字略記 (「白」「戦」) は**当てない** — 別のジョブやアビリティ名に
  誤爆する。当たらなければ絞らず全部出す。

**実測**: dev preview に合成した軽減表の一時ページを置き、`アドル (赤魔道士)`
等の列ラベルから 5 列すべてジョブが解決 → 赤魔道士で「自分のロール」=
アドル + 牽制 (侍)、「自分の担当だけ」= アドルのみ、チップの色が
暗黒騎士=青 / 学者・白魔道士=緑 / 赤魔道士・侍=赤 になることを確認
(一時ページは削除済み)。

**残る実機確認**: 実物の軽減表 (見出しがアイコン画像のシート) で列ラベルの
ジョブ名が読めるかは、マージ後に画面で 1 回見てほしい。読めない列があれば
`アビリティ名` の登録で `名前 (ジョブ)` の形に直せば当たる。

### W-10. 軽減表の雛形を pull から作る — 2026-09-08 実装 / W-9・UI-13 は据え置き

pull の展開行から「軽減表の雛形を作る」を押すと、その pull でボスが撃った
大きい技を `時刻 / 技名 / 対象人数 / 合計 / 最大` の表にし、**Sheets に
貼れるタブ区切り**でコピーできる。

- ⚠ **畳み方が本題。** 被ダメージは 1 ヒット = 1 件で返るので、全体攻撃は
  8 人ぶん並ぶ。「同じ技 × **その行の先頭から** 0.7 秒以内」で 1 行に畳む。
  - 丸めにしない: 境界をまたいだ同じ攻撃が 2 行に割れる
  - 「直前のヒットから」にしない: **一定間隔の継続ダメージが際限なく
    1 行に繋がる** (0.6 秒刻みの技が 1 行になり対象人数が数十になる)
  - 検査でこの 3 通りを固定してある
- ⚠ **軽減の判定と率の計算はしない** (許可リストの保守が続かない。W-8 と
  同じ判断)。合計 2 万未満の行は継続ダメージとして落とす。
- ⚠ **押したときだけ取り、保存しない** (1 pull で数百件返る)。
- **W-9 / UI-13 の据え置き理由**: シートの技名は固定ごとの略称で FFLogs の
  正式名と一致せず、突き合わせると「合っているのに合っていないと出る」方が
  害が大きい。ノート自身が「8.0 の軽減再編後が保守的に有利」と書いている。

## 運用上の注記 (実機で判明したこと)

### デモサイトのデータは `supabase/seed-demo.sql` の Section 3 (2026-09-08)

デモに直接 SQL を打たない。`seed-demo.sql` は main push で
`deploy-database-demo.yml` が demo project へ自動適用する (schema.sql と同じ
経路)。追加するときは**新しい sentinel を持つ節**を足す — 既存の
`demo_seed_applied` は 2 回目以降スキップするので、既に適用済みの demo に
対して新しい節だけを 1 回走らせるにはこれが必要。

- ⚠ **seed は CI で実行されない。** 実行時エラーはデプロイまで出ない。
  `scripts/check-seed-sql.mjs` が「列名」と「ON CONFLICT の列組」を
  schema.sql と突き合わせて CI で止める (2026-09-08 に
  `fflogs_report_videos` の主キー差し替えを見落として実際に踏んだ)。
  構文は libpg_query で別途見られる (下の注記)。
- 日付は**適用時の JST 今日から逆算**する。固定日を焼くと数か月で
  「半年前のログしか無いデモ」になる。
- デモは **native モード**。sync (外部シート) では出欠系の追加機能が
  データを入れても画面に出ない。
- 運用台帳系 (`fflogs_report_syncs` / `fflogs_notify_state` /
  `fflogs_report_blocklist`) は**意図的に入れていない**。同期の「未取得
  レポート」や通知の抑制状態を偽装すると、デモを見た人が挙動を誤解する。

### seed / schema の SQL はローカルで構文検証できる

`pip install pglast` (libpg_query = 本物の Postgres パーサ) を入れると、
`parse_sql` で外側の SQL、`parse_plpgsql_json` で `DO $$ … $$` の中身を
push 前に検証できる。**`DO` ブロックの中は SQL パーサからは不透明な文字列**
なので、両方を通す必要がある。

### `scripts/check-*.mjs` は Windows でも走る (2026-09-08)

全 48 本を手元 (Windows) で `for f in scripts/check-*.mjs; do node "$f"; done`
まで通した。tsc の起動は `execFileSync(process.execPath,
["node_modules/typescript/bin/tsc", ...])` に統一してあり、**`npx` に戻すと
Windows で ENOENT / EINVAL になって 1 本も走らなくなる** (CI の ubuntu では
通るので気付けない)。`check-ja-strings.mjs` は同じ理由で走査パスを `/` に
正規化している (`\` は `EXCLUDE` にも `BASELINE` の `src/lib/...` 表記にも
一致せず、全ファイルが未登録扱いになる)。

### 2026-09-08 に schema.sql の再実行が要る

UI-2 (コンテンツカードのスパークライン) で関数を 1 本足した
(`category_progress_by_day`、schema.sql の 13c-3 節)。再実行していない
デプロイでは**カードの線が出ないだけ**で、他の機能には影響しない。
GitHub Actions の自動反映を設定済みなら main push で当たる。

### W-5 レポート自動発見は、この固定では実質使えない

実装済みだが、2026-09-07 の実機確認で前提が満たせないことが分かった。

- **「自分のアカウントから」は Public のレポートしか拾えない**。診断パネルの
  実測で、返ってきた 12 件はすべて 2022 年以前だった (最近のレポートは
  Unlisted)。session cookie による scrape も 403。
- **「guild から自動」には前提が 2 つある**。`Report.guild` は「null なら
  ユーザーの個人ログにアップロードされたレポート」で、所属は**アップロード時に
  決まる** — Uploader でアップロード先に guild を選んでいなければ `guildID` で
  引いても 0 件で、**既存の履歴は後から移せない**。加えて一覧が Unlisted を
  返すかは未確認 (v2 のスキーマは `report(code:)` にだけ `allowUnlisted` を
  持ち、一覧の `reports()` には可視性の引数が無い)。

→ Unlisted 運用を続ける限り、確実なのは**従来の URL 貼り付け**。設定画面の
ブックマークレットでレポート一覧から URL をまとめて拾える。前提は
`docs/guides/log-runner.md` と設定画面の説明文にも書いてある。

**未実装の選択肢**: 「発見元の接続テストボタン」(同期を回さず 1 クリックで
0 件かどうかを見る)。押しても「0 件」としか出せず原因を説明できないため、
前提の明示を優先して作っていない。要望があれば作る。

### 動画オフセットは「基準の pull」を取り違えやすい

2026-09-07 に「リンクが 104 秒ずれる」報告があり、原因は**動画に最初の pull が
映っておらず** (録画開始が 82 秒後)、0:22 で始まっていたのが 2 本目の pull
だったこと。計算式は正しかった。オフセット欄の下に値の意味を実時刻で出す
表示を追加済み (`explainOffset`)。同種の報告が来たら、まずその 2 行を見てもらう。
