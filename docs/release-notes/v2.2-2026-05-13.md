## 🐛 PR #125 — Lightbox の ← → キーと画像左右半分クリックでの前後遷移を本対応 (PR #124 の後追い fix)

**経緯**: PR #124 で Lightbox の前後遷移 3 経路 (左右 chevron ボタン / キーボード ← → / タッチスワイプ) を実装したが、ユーザー実機確認で **← → キーと、画像本体クリックでの遷移 (これは PR #124 にはなかった追加要望) の 2 経路が動かない** と報告。chevron ボタンとスワイプは正常動作。

**真因 1 (← → キー)**: `window.addEventListener('keydown', handler)` を bubble 段階で登録していたが、Lightbox を実装している base-ui の `DialogContent` がキーイベントを bubble 段階で `stopPropagation()` しているため、event が window まで届かず handler が発火しない。capture 段階で登録すれば DialogContent より先に走るので影響を受けない。

**真因 2 (画像クリック)**: PR #124 ではそもそも画像本体クリックに前後遷移を割り当てておらず (左右 chevron ボタンと swipe のみ)、画像クリックは「閉じる」しか挙動がなかった。今回追加要望として画像左右半分クリックでの遷移を新規実装。

**変更内容**:
- **編集** [strategy-images-list.tsx](src/app/(portal)/category/[slug]/strategy/strategy-images-list.tsx): Lightbox 内 keydown handler の `addEventListener` / `removeEventListener` 第 3 引数を `true` (capture) に変更し、base-ui の bubble 段階 stopPropagation を回避
- **編集** 同ファイル: `<img>` の `onClick` で `event.stopPropagation()` (背景クリック = 閉じる の発火抑止) → `event.currentTarget.getBoundingClientRect()` で要素中央 X を算出 → クリック X が中央より左なら `goPrev()`、右なら `goNext()`。単独画像 (集合サイズ 1) のときは onClick を登録せず `cursor` も default のまま (誤クリック防止と視覚的な「ここは遷移できない」の明示)

**検証**: dev preview で複数枚アルバム / 単独画像の両方を Lightbox で開き、← → キー / 画像左半分クリック / 画像右半分クリック / 画像中央 (どっち寄りに当たるかは画像幅次第) で前後遷移が機能、画像外余白クリックで閉じる (PR #119 の修正と非干渉) を確認。

## 🐛 PR #119 — 攻略画像 Lightbox の画像外クリックで閉じる挙動を修正 (<Image fill> letterbox 透明域問題)

**経緯**: PR #118 (Phase 15) で導入した攻略画像 Lightbox は背景 (画像外) クリックで閉じる UI として実装したが、実機では画像周辺の余白をクリックしても閉じない症状が報告された。

**真因**: Next.js `<Image fill>` を使うと img element は親 box (Lightbox container) 全体を `inset: 0` で覆い、`object-fit: contain` で画像本体は中央に描画されるが、画像のない letterbox 透明域も依然として img element の hit area に含まれる。つまり「画像外」を狙ったクリックも実は img の上に落ちており、img の onClick / 背景 onClick の前に止まる挙動になっていた。

**変更内容** [strategy-images-list.tsx](src/app/(portal)/category/[slug]/strategy/strategy-images-list.tsx): `<Image fill>` を素の `<img>` + `max-h-full max-w-full object-contain` に置き換える。これにより img の box が natural aspect (画像の縦横比) に絞られ、letterbox 透明域は img element の外側になるので、周囲余白クリックは親 div の handler に正しく届く。画像本体クリックは img 側で `event.stopPropagation()` して閉じない (Lightbox 内で何かの操作中に誤って画像をクリックしても閉じない安全策)。Next.js 画像最適化を捨てる形になるが、Lightbox 内は元々 high-res で見たいユースケースなので最適化スキップは許容判断。

**検証**: dev preview で Lightbox を開き、画像本体クリック (閉じない) と画像外余白クリック (閉じる) の両挙動を確認。
